# 코드 변경 카드

`src/` 계열 파일을 편집할 때 로드된다. 일반적인 코딩 상식은 담지 않는다.
**모델이 반복해서 틀리는 것**만 남긴다.

## 구현 사다리 (쓰기 전)

새 코드를 쓰기 전에 위에서부터 훑고 **걸리는 첫 단에서 멈춘다.**
0단(「이게 존재해야 하는가」)의 정본은 T0 「최소 수정」이다 — 여기서는 그 다음부터 다룬다.
하네스 자산의 「해결 수단 우선순위」(`harness-change.md`)와 같은 형태이고, 이건 앱 코드 쪽 대칭이다.

| 단 | 묻는다 | 걸리면 |
| --- | --- | --- |
| 1 | 이 저장소에 이미 있는가 | grep으로 찾아 재사용. 몇 파일 건너에 있는 것을 다시 쓰는 것이 가장 흔한 낭비다 |
| 2 | 표준 라이브러리·런타임이 하는가 | 쓴다 |
| 3 | 플랫폼 네이티브가 하는가 | DB 제약 > 앱 코드, CSS > JS, `<input type="date">` > 피커 라이브러리 |
| 4 | 이미 설치된 의존성이 하는가 | 쓴다. **신규 추가는 아래 「의존성 추가 전」** |
| 5 | 한 줄로 되는가 | 한 줄로 쓴다 |
| — | 다 아니면 | 작동하는 최소 구현 |

두 단이 동시에 걸리면 위쪽을 택하고 넘어간다. 사다리는 반사이지 조사 과제가 아니다.

**사다리는 해결을 줄이지 이해를 줄이지 않는다.** 변경이 닿는 파일과 실제 흐름을 먼저
추적한 뒤에 오른다. 이해를 건너뛴 작은 diff는 효율이 아니라 자신 있는 오답이다.

**깎지 않는 것** — 신뢰 경계의 입력 검증 · 데이터 손실을 막는 에러 처리 · 보안(`security.md`) ·
접근성 기본 · **비자명한 로직의 검증 장치**(분기·루프·파서·금액/보안 경로는 한 줄로 줄여도
실행 가능한 검사 하나를 남긴다) · 사용자가 명시 요청한 것.
되돌림 클래스가 **Costly 이상이면 명시성이 간결함을 이긴다** — 사다리는 돌되 결과를 짧게
만드는 쪽으로 기울이지 않는다.

**사후 정리는 여기가 아니다** — 이미 쓴 코드를 줄이는 것은 내장 `/simplify`다.
이 절은 쓰기 전에만 적용된다.

**천장을 아는 축약은 표시한다** — 의도적으로 모서리를 자를 때(전역 락 · O(n²) 스캔 ·
순진한 휴리스틱) 주석 한 줄을 남긴다: `EPCC-SHORTCUT: <천장>, <해제 조건>`.
해제 조건 없는 마커는 "나중에"가 "영원히"가 되는 자리다 — `/shortcut-ledger`가 회수한다.

## 변경 후 역추적

변경한 변수·함수를 grep해서 미사용 잔재를 정리한다. 개선을 하고 옛 코드를 남기는 것이
가장 흔한 실패다. 변수명이 바뀐 역할과 여전히 일치하는지 확인한다.

## 동일 패턴 전파

정규식·상수·시그니처를 바꿨으면 grep으로 **사용처를 전수 검색**해서 일괄 변경한다.
한 곳만 고치면 나머지가 조용히 어긋난다.

## 배선 확인 (존재 ≠ 실행)

규칙·상태값·핸들러를 도입할 때 CRUD 전 생명주기의 **실행 배선**을 확인한다.
"파일이 존재하는가"가 아니라 **"누가·언제 호출하는가"**까지 확인한다.

- 파일에 append하는 코드를 쓰면 로테이션/상한을 같이 넣는다
- 비정상 종료 시나리오를 고려한다
- 새 분기를 넣으면 그 분기로 실제 들어가는 입력이 있는지 확인한다

## 참조 신선도

이전 작성물을 인용·확장하기 직전의 4축 점검은 `.claude/rules/workflow-routing.md`가
매 세션 로드한다 — 인용 시점은 `src/` 편집과 무관하므로 그쪽이 정본이다.

## 공유 경계 (수정 전 확인)

공유 패키지(`packages/**` · 모노레포 워크스페이스 · 사내 배포 라이브러리)를 고치기 전에
**소비처를 grep으로 전수 조사해 목록을 먼저 제시하고 사용자 확인을 받는다.**
소비처가 이 저장소 밖에 있을 수 있고, 그때 영향 반경은 grep으로도 안 보인다.

앱 코드에서 해결 가능한 문제를 공유 패키지 수정으로 푸는 것은 범위 확대다 —
"거기가 더 맞는 자리"는 별도 요청이 있을 때 한다.

## 검증까지가 한 동작

소스를 고쳤으면 **빌드/테스트 실행 → 결과 확인**까지 해야 변경이 끝난다.
`build-gate` 훅이 이를 강제하지만, 훅이 막기 전에 스스로 한다.

## 되돌림 클래스별 추가 요구

| 클래스 | 추가 |
| --- | --- |
| Irreversible | 적용 전 사용자 확인 필수. 롤백 절차를 함께 제시. 검증은 `epcc-reviewer` 다관점 팬아웃 |
| Costly | 영향 범위(호출처 목록)를 먼저 제시. 검증은 `epcc-reviewer` — 자기 리뷰로 대체하지 않는다 |
| Reversible | 없음 — 바로 진행 |

## 의존성 추가 전 (설치 후 audit이 아니라 설치 전 점검)

새 패키지는 설치 전에 5가지를 점검한다: ①출처(공식 레지스트리·활성 저장소)
②이력(최근 업데이트·메인테이너 변경) ③의존성 트리(수상한 transitive 포함)
④커뮤니티 규모(다운로드·이슈 대응) ⑤패키지 매니저 audit — **Critical/High 발견 시
설치 중단 후 사용자 보고**. 10줄로 대체 가능한 기능이면 의존성을 추가하지 않는다.

## 자가 점검 (구현 완료 시)

- 요청하지 않은 파일을 고쳤는가
- "확장성을 위해" 추가한 코드가 있는가
- 제거해도 요청 기능이 동작하는 코드가 있는가

→ 하나라도 YES면 제거한다.
