# 하네스 변경 카드

훅·규칙·스킬·에이전트·스크립트를 건드릴 때 로드된다.

> **경로 표기** — `<플러그인-루트>/…`는 플러그인이 배송한 자산이다(절대 경로는 매 세션
> 브리핑의 「자기검증」 줄에 있다). `.claude/…`는 프로젝트 소유다. 이 카드는 플러그인
> 저장소와 소비자 프로젝트 **양쪽에서** 로드되므로, 어느 한쪽에서만 참인 상대 경로는
> 쓰지 않는다 — 그것이 아래 「변경 후 역추적」이 경고하는 배포 맥락의 거짓이다.

> **핵심: Script가 할 수 있는 것은 Script에, LLM만 할 수 있는 것은 LLM에.**

## 추가 전 3-질문

| # | 질문 | YES면 |
| --- | --- | --- |
| Q1 | 기존 훅/규칙/스킬/**Claude Code 빌트인**과 역할이 겹치는가 | **중단** — 기존 것을 확장하거나, 빌트인을 쓰거나, 빌트인 위에 부족분만 얇게 덧댄다(합성) |
| Q2 | 향상된 모델 성능 덕에 이제 불필요한 것 아닌가 | **중단** |
| Q3 | 이미 잘 동작하는 것을 굳이 바꾸는 건 아닌가 | **중단** |

Q1의 "빌트인"은 실제로 확인한다. `/code-review`, `/simplify`, `/security-review`,
`skill-creator`, `/init`, `/run`, `/loop`은 Claude Code가 제공한다. **이들과 경쟁하는
자산을 만들지 않는다.**

**빌트인은 모델과 함께 계속 좋아진다.** 그래서 이 비교는 한 번 하고 끝나지 않는다 —
자산을 손댈 때마다 다시 던진다.
판정은 셋이다: **네이티브로 대체 · 커스텀 유지 · 합성.** 셋째를 고르면 커스텀은 빌트인을
**감싸는 얇은 층**이어야 하며, 빌트인이 이미 하는 일을 재구현해서는 안 된다.

## 해결 수단 우선순위

```
1. 기존 문서 수정 (1~3줄 추가)        ← 가장 선호
2. 기존 훅 로직 확장
3. 기존 스크립트에 기능 추가
4. 신규 스크립트 작성                  ← 가장 후순위
```

## 플랫폼 동작은 확인하고 주장한다

"Claude Code는 이렇게 동작한다"를 전제하기 전에 **`<플러그인-루트>/docs/platform-contract.md`를 본다**
(치환 변수 · 컴포넌트 자동 발견 · `.claude/rules/` 로딩 · 이벤트별 출력 규격 · 서브에이전트).
없으면 **공식 문서를 확인해 출처 URL과 확인 날짜를 적어 추가한다.** 기억으로 단정하지 않는다.

> 이 규율이 없어서 치환되지 않는 자작 변수 표기가 28곳까지 자랐고,
> `.claude/rules/`가 네이티브 기능인 줄 몰라 작업 라우팅을 갱신 경로가 없는 곳에 두었다.

## 차단 장치는 3상태다 — 판정 불가를 차단으로 접지 않는다

| 상태 | 행동 |
| --- | --- |
| 위반 확인 | 차단 |
| 위반 없음 확인 | 통과 |
| **판정 불가** (의존 도구 부재 · 입력 없음 · 오프라인) | **차단하지 않는다.** 판정 불가임을 명시 보고하고 통과 |

판정 불가를 차단으로 접으면 오탐이 되고, **오탐은 사용자가 훅을 꺼버리게 만들며,
꺼진 훅의 차단력은 0이다.** 없음으로도 있음으로도 단정하지 않는다.
(선례: `<플러그인-루트>/scripts/build-gate.sh`의 `UNDECIDABLE` ·
`<플러그인-루트>/scripts/guide-freshness.sh --offline`)

**면제는 첫 토큰으로 판정한다 — 문자열 포함(`*x*`)으로 면제하지 않는다.** 차단 장치의 예외는
"이 명령이 무엇을 실행하는가"(첫 토큰·부명령)로 열고, 명령이 연결자(`;` `&&` `||`)로 이어지면
세그먼트마다 따로 판정한다. 명령 어딘가에 `doctor.sh`가 있으면 통과시키던 면제가
`…doctor.sh …; psql -c "DROP TABLE"`을 통째로 통과시켰다(평가 v6 · E-21) — 면제는 차단 지점과
같은 강도로 픽스처가 증명해야 한다(우회 시도 픽스처 → exit 2).

## 침묵 실패 방지 (필수)

새 훅·스크립트를 만들거나 고쳤으면 **아래를 실제로 실행**한다. 생략 불가.

1. `<플러그인-루트>/scripts/lib/common.sh`를 source하고 `epcc_begin`으로 시작한다
   (플러그인 밖 자체 훅이라면 이 lib에 의존하지 말고 같은 규율 — 루트 확정 실패 시 exit 2,
   숫자 검증, 이벤트별 출력 규격 — 을 자체 구현한다)
   — 루트는 `epcc_root()`로만 구한다. `BASH_SOURCE`, `dirname ../..` **금지**
   — 숫자는 `epcc_num()`을 통과시킨다. `|| echo 0` **금지**
2. 출력은 `epcc_emit_context` / `epcc_emit_block`으로만 한다
   — 이벤트마다 지원 필드가 다르다. 미지원 필드는 **조용히 무시**된다
   — Stop은 `decision`/`reason`을 지원하지 않는다 (`continue`+`systemMessage` 사용)
   — PreCompact/SessionEnd는 평문 stdout이 컨텍스트에 들어가지 않는다 (JSON 필요)
3. `bash "${CLAUDE_PLUGIN_ROOT:-.}/scripts/doctor.sh" --default` + `--self-test` → 통과 확인

## 개입 근거 2줄 — 재실행 증거 없는 개입은 미완성이다

개입(훅·규칙·스킬·브리핑 무엇이든)을 추가·수정했으면 커밋 메시지나 PR에 두 줄을 적는다.

| 줄 | 내용 |
| --- | --- |
| (a) | **막으려는 실패** — 2회 이상 반복 관측된 것 |
| (b) | **잘 되던 것을 망칠 위험** |

(a)를 못 쓰면 그것은 가설이지 패턴이 아니다 — 추가하지 않는다.
개별 사례의 정답을 하드코딩하지 않는다. 다음 작업에도 재사용되는 개입만 남긴다.

그리고 `--self-test`가 통과해야 한다. **그럴듯한 수정과 효과 있는 수정은 다르고,
둘을 가르는 것은 재실행뿐이다.** 위 "차단을 증명한다" 규율을 차단 장치뿐 아니라
모든 개입에 적용한다.

## 도달 경로 검증

규칙·점검 장치를 추가할 때 **그 파일이 의도한 시점에 실제로 로드되는지** 즉시 확인한다.

- `paths:` 조건부 로딩이면 대상 파일의 paths가 실제 편집 경로를 포함하는가
- 세션 브리핑의 「훅 n/n 정상」이 실제로 그 수를 보고하는가 — 등록만으로는 산 것이 아니다

## 변경 후 역추적 — 사라진 이름 쪽을 본다

앞 절이 **새 이름이 닿는가**를 본다면, 이 절은 **옛 이름을 가리키던 것들**을 본다.
개명·이동·삭제는 한 종류의 사건이다. 개명된 자산은 새 이름으로 잘 놓여 있으므로
**「도달 경로 검증」을 언제나 통과한다** — 잔재는 사라진 이름 쪽에 남고, 그쪽을 보는 검사가 없으면
영원히 안 잡힌다. (`code-change.md`의 「변경 후 역추적」·「동일 패턴 전파」가 앱 코드 쪽 대칭이다.)

1. **사라지는 이름 목록을 먼저 확정한다.** 기억에서 꺼내지 않는다 —
   `git diff --diff-filter=RD --name-only`와 `.claude/deprecated/`의 파일명이 목록의 출처다.
   자리표시자(`<폐기한 것들>`)를 남기면 사람이 채우다 빠뜨리고, 빠뜨린 이름은 검사가 아예 없는 것과 같다
2. **저장소 전체를 훑는다.** `.claude/`만이 아니라 저장소 전체다 —
   `README.md`·`docs/`·`dev/`가 빠지는 자리다
3. **0건을 명령으로 확인한다.** 체크리스트에 「전수 확인함」이라 적는 것은 증거가 아니다

> **명령이 곧 사실이고, 문장은 아니다.** 실측: 포트 Phase 4의 완료 조건은 "구 이름 참조가
> **저장소 전체**에서 0건"이라고 적었지만 실행된 명령은 `.claude/`와 `CLAUDE.md` 두 곳만 봤다.
> 지시 명령에는 있던 `dev/`가 검증 명령에서 빠졌고, 정확히 거기에 옛 이름이 남았다.

## 자산 부재 판정 — 3-위치 검색

Agent·Skill·Hook·플러그인이 "없다"고 단정하려면 세 곳을 **모두** 확인한다:

1. 프로젝트 로컬 `.claude/`
2. 플러그인 캐시 `~/.claude/plugins/cache/`
3. 마켓플레이스 `~/.claude/plugins/marketplaces/`

한 곳만 보고 "없음"이라 결론내지 않는다. 특히 부재를 근거로 새 자산을 만들기 전에.

## 폐기 프로토콜 — Shadow 미러

**소비자 프로젝트의** `.claude/` 자산(규칙·스킬·훅 커스텀)을 폐기할 때 즉시 삭제하지 않는다.
`.claude/deprecated/`로 이동하고 만료일을 파일명에 새긴다 (기본 14일):

```
.claude/skills/foo/SKILL.md → .claude/deprecated/skills_foo_SKILL.md.shadow-expires-2026-09-03
```

만료까지 문제가 없으면 삭제 확정, 문제가 생기면 원위치 복구(롤백).
만료분은 `doctor --lessons`가 보고한다. 폐기 결정은 항상 사용자 승인을 거친다.

## 에이전트 예외

에이전트는 `.claude/rules/`를 상속받지 않는다. 에이전트에 필요한 규범은
**해당 에이전트 프롬프트에 직접** 기재한다. 규칙 파일로 대신하려 하지 않는다.
단 같은 규범을 두 곳이 주장하게 두지 않는다 — 한 곳이 원본이고 다른 곳은 인용이다.
