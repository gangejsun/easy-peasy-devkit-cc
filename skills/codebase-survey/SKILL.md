# Codebase Survey

**측정하고 서술한다. 처방하지 않는다.**

`/epcc-init`이 최초 1회 실측해 만든 프로젝트 소유 카드 두 장은 그 뒤로 **갱신 경로가 없다**
(프로젝트 소유라 버전 스탬프도 없어 드리프트를 감지할 장치조차 없다). 코드가 자라면 카드는
조용히 거짓이 되고, 거짓 카드는 없는 카드보다 나쁘다. 이 스킬이 그 갱신 경로다.

> **경계** — 스택을 *고르는* 것은 `/epcc-init`, 가이드를 *만드는* 것은
> `/stack-guide-generator`, 이번 변경의 *영향 반경*을 재는 것은 `epcc-planner`,
> 빌드·테스트가 *도는지* 보는 것은 `/health-check`다. 이 스킬은 그 넷이 다루지 않는
> **저장소 전체의 현재 사실**을 맡는다. 코드를 고치지 않고, 구조를 바꾸지 않는다.

## Step 0: 프로젝트 하네스 인벤토리 — 읽기만 한다

소비자가 원래 갖고 있던 것을 먼저 찾는다. **하나도 고치지 않는다**
(`.claude/rules/workflow-routing.md` 「지시 우선순위」의 비침습).

```bash
ls -a
ls AGENTS.md CODEX.md CLAUDE.md README.md CONTRIBUTING.md 2>/dev/null
ls -d .github .gitlab .gitlab-ci.yml docs .harness .agents .cursor 2>/dev/null
ls .claude/rules/ 2>/dev/null
```

찾은 것은 **읽어서 목록으로 보고**한다. 여기에 적힌 규약이 이후 모든 판단에서
플러그인 가이드를 이긴다 — 그래서 측정보다 먼저 온다.

자산이 "없다"고 단정하기 전에 세 곳을 모두 본다: 프로젝트 로컬 `.claude/` ·
플러그인 캐시 `~/.claude/plugins/cache/` · 마켓플레이스 `~/.claude/plugins/marketplaces/`.

## Step 1: 실측 — 추측 금지

명령 블록의 정본은 `/epcc-init` Step 0이다. **여기에 옮겨 적지 않는다** — 그 단계를 읽고
같은 것을 돌린 뒤, 아래를 더한다 (init은 프리셋 기본값을 채우려 재고, 여기는 저장소의
현재 형태를 재기 때문이다):

```bash
git log --oneline -1 && git rev-parse --abbrev-ref HEAD    # 어느 시점의 사실인가
cloc . 2>/dev/null || find . -type f -name '*.*' -not -path '*/node_modules/*' \
  -not -path '*/.git/*' | sed 's/.*\.//' | sort | uniq -c | sort -rn | head -15
ls -d */ && ls -d src/*/ app/*/ packages/*/ 2>/dev/null   # 상위 2 depth
ls -d services/*/ apps/*/ 2>/dev/null                     # msa 여부
grep -o '"repoTopology"[^,}]*' epcc.config.json 2>/dev/null  # 선언값 — 실측과 대조한다
```

락파일·매니페스트·설정 파일이 진실이다. **읽어서 확인한 것만 적는다** — 프리셋이나
프레임워크 관례로 단정하지 않는다. 확인할 수 없는 항목은 「미확인」으로 남기고 묻는다.
**없는 것과 못 읽은 것은 다르다** — 둘을 같은 칸에 적지 않는다.

## Step 2: 아키텍처 서술 — 처방하지 않는다

여섯 가지만 본다. 각 항목은 **파일 경로로 뒷받침**한다. 경로를 댈 수 없으면 적지 않는다.

| 항목 | 무엇을 찾는가 |
| --- | --- |
| 진입점 | 라우트·핸들러·CLI·잡·워커 — 외부 요청이 코드로 들어오는 자리 |
| 레이어 | 저장소가 실제로 쓰는 구획과 **import가 실제로 흐르는 방향** (있는 그대로. 없으면 「단층」) |
| 데이터 흐름 | 요청 → 검증 → 비즈니스 로직 → 저장소 → 응답의 실제 경로 1개를 추적 |
| 신뢰 경계 | 외부 입력이 들어오는 지점과 인증·인가가 걸리는 지점 |
| 반복 패턴 | 3회 이상 같은 형태로 나타나는 것 — 이것이 이 저장소의 컨벤션이다 |
| 위험 구역 | 되돌림 클래스가 Costly 이상인 경로 (마이그레이션·auth·결제·공유 패키지·public API) |

**있는 것을 설명하고, 없는 것을 권하지 않는다.** Clean Architecture · DDD · MVC ·
리포지토리 패턴 · 이벤트 소싱을 저장소가 쓰지 않으면 **제안하지 않는다.** 개선안은
사용자가 물었을 때만 내고, 그때도 현재 경계 **안에서의** 개선을 먼저 놓는다.

## Step 3: 카드 갱신 + 드리프트 보고

`.claude/rules/` 아래의 `project-structure.md`와 `code-conventions.md`를 **갱신**한다
(두 카드는 프로젝트 소유라 플러그인 저장소에는 없다 — 소비자 프로젝트에서만 실재한다).
새 문서를 만들지 않는다 — 새 문서는 로드 시점이 없고, 로드되지 않는 문서는 비용만 있다.

| 상태 | 처리 |
| --- | --- |
| 카드 없음 | 템플릿(`${CLAUDE_PLUGIN_ROOT}/templates/rules/*.template.md`)에서 생성. 절차는 `/epcc-init` Step 7.5 |
| 카드 있음 · 실측과 일치 | 건드리지 않는다. 「일치」로 보고 |
| 카드 있음 · **어긋남** | 항목별 diff를 제시하고 **사용자 확인 후** 갱신 |

**항목별 diff가 이 스킬의 산출물이다.** 카드를 통째로 덮어쓰지 않는다 — 사람이 손으로
넣은 프로젝트 고유 규약이 그 안에 섞여 있고, 통째 교체는 그것을 조용히 지운다.

```
project-structure.md
  − packages/shared/       (카드에 있으나 실물 없음 — 제거됨?)
  + src/features/billing/  (실물에 있으나 카드에 없음)
  ~ paths: "src/**"        (실제 소스는 app/ — 카드가 영영 로드되지 않는 상태)
```

Step 2의 「레이어」 실측은 `project-structure.md`의 **「의존 방향」 절**로 들어간다.
방향이 관측되지 않으면 「단층 — 해당 없음」이라고 적는다 — 있지도 않은 레이어를
카드에 세우지 않는다. 이 절이 비어 있으면 `epcc-reviewer`의 역행 import 대조가
판정 불가로 남는다.

`paths:`가 실제 소스 경로를 덮는지 **반드시 확인한다.** 어긋나 있으면 그 카드는 지금까지
한 번도 로드되지 않은 것이고, 그것이 가장 먼저 보고할 사실이다.

두 카드에 `epcc-rule-version` 스탬프를 **넣지 않는다** (프로젝트 소유 표시).

### 세 번째 대조 대상 — `epcc.config.json`의 `repoTopology`

토폴로지는 `/epcc-init`이 **프로젝트가 가장 작을 때** 한 번 묻고 기록한다. 그 뒤로 이 값을
다시 보는 곳이 없어서, 저장소가 자라면 선언과 실물이 갈라진다. **실측이 선언을 이긴다.**

| 실측 | 선언 | 처리 |
| --- | --- | --- |
| `packages/`·`services/`·`apps/` 없음 | `single` | 일치 |
| `packages/`에 워크스페이스 2개 이상 | `single` | 드리프트 — `monorepo` 승격 제안 |
| `services/`·`apps/`로 서비스 분리 | `single`·`monorepo` | 드리프트 — `msa` 제안 |
| 필드 없음 | — | 미설정 — 보고만 한다. 추측으로 채우지 않는다 |

**값보다 결과가 먼저다.** 어긋났으면 `project-structure.md`의 `paths:`를 같이 본다 —
새 워크스페이스 경로(`packages/**` 등)가 거기 없으면 **그 카드는 새 코드 위에서 한 번도
로드된 적이 없다.** 공유 패키지는 `reversibility.md`가 **Costly**로 분류하는 자리이므로,
카드가 안 뜬다는 것은 되돌림 판정의 근거가 빠진 채 편집돼 왔다는 뜻이다.
config 값 갱신보다 이 사실을 먼저 보고한다.

## Step 4: 검증 경로 확정

빌드·테스트·린트 명령을 실측하고 **실제로 한 번 돌려** 존재를 증명한다.
"스크립트에 적혀 있다"는 "동작한다"가 아니다.

`epcc.config.json`의 `techStack.commands`와 다르면 보고한다 — `build-gate` 훅이 그중
`build`·`test`를 읽어 턴 종료 시 돌린다(`scripts/build-gate.sh:85-86`). 어긋나 있으면 훅이
엉뚱한 명령을 돌리거나 값이 비어 「판정 불가」로 매번 통과시키고 있다는 뜻이다.

드리프트가 1건 이상이면 마지막 줄에: `카드 N건 갱신할까요? (항목별로 고를 수 있습니다)`

## 상한

아키텍처 서술은 **레이어당 대표 경로 3개까지**다. 파일을 전부 나열하지 않는다 —
`ls`로 되는 것을 스킬이 대신할 이유가 없고, 나열은 서술이 아니다.
저장소가 커서 한 번에 못 담으면 **위험 구역부터** 채우고 잔여 범위를 밝힌다.
