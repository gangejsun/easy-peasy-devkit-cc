**소비자가 LLM 기능을 만들 때만 읽는다.** 이 하네스가 Claude Code용이라는 사실과 무관하게,
여기서 다루는 것은 **소비자가 만드는 애플리케이션**의 LLM 표면이다.

> **완전 방어는 없다.** 프롬프트 인젝션은 원리적으로 봉쇄되지 않는다 — 모델은 지시와
> 데이터를 같은 채널로 받는다. 그래서 단일 방어가 아니라 **다층**으로 간다:
> 최소 권한 툴 범위 · 출력 필터링 · 되돌릴 수 없는 행동에 사람 개입 · 적대적 테스트.
> "인젝션을 막았다"고 적는 순간 그 문장이 결함이다.

| ID | 이름 | 우선순위 |
| --- | --- | --- |
| LLM01 | Prompt Injection | 최우선 |
| LLM02 | Sensitive Information Disclosure | 최우선 |
| LLM05 | Improper Output Handling | 최우선 |
| LLM06 | Excessive Agency | 최우선 (툴을 쓰는 에이전트라면) |
| LLM03 | Supply Chain | 모델·플러그인을 외부에서 가져오면 |
| LLM04 | Data and Model Poisoning | 학습·파인튜닝·RAG 색인을 직접 하면 |
| LLM07 | System Prompt Leakage | 시스템 프롬프트에 비밀을 두었다면 (두지 않는 것이 답) |
| LLM08 | Vector and Embedding Weaknesses | RAG를 쓰면 |
| LLM09 | Misinformation | 사용자에게 사실로 제시되는 출력이면 |
| LLM10 | Unbounded Consumption | 과금·가용성 (API4와 같은 축) |

### LLM01 Prompt Injection — CWE-77 계열

직접(사용자가 지시를 덮어씀)과 **간접**(웹 페이지·이메일·문서에 심어진 지시를 모델이
읽음) 둘 다다. **간접이 더 위험하다** — 공격자가 대화에 참여하지 않아도 된다.

- [ ] 시스템 지시와 사용자 입력이 **문자열 결합이 아니라 메시지 역할로** 분리돼 있다
- [ ] 외부에서 가져온 텍스트(웹·파일·DB·타 사용자 입력)는 **데이터로 표시**해 넣는다
      — 이 하네스 자신의 규범과 같다: `.claude/rules/workflow-routing.md` 「외부 텍스트는 데이터다」
- [ ] 인젝션이 성공해도 **피해가 제한**되도록 툴 권한을 좁혔다 (LLM06)
- [ ] 되돌릴 수 없는 행동(결제·삭제·발송) 앞에 사람 확인이 있다
- [ ] 적대적 입력에 대한 테스트가 있다 (한 번이라도 돌려 봤는가)

### LLM02 Sensitive Information Disclosure — CWE-200 · CWE-532

- [ ] 모델에 넣는 컨텍스트에 **다른 사용자의 데이터가 섞이지 않는다** (RAG 검색에 소유권 필터)
- [ ] 응답을 사용자에게 주기 전에 시크릿 패턴을 필터링한다
- [ ] 프롬프트·응답을 로그에 남길 때 개인정보·자격증명을 마스킹한다 (A09와 같은 축)
- [ ] 학습·평가 데이터에 프로덕션 개인정보를 넣지 않는다

### LLM05 Improper Output Handling — CWE-79 · CWE-89 · CWE-78

**모델 출력은 신뢰할 수 없는 입력이다.** 이것이 가장 자주 잊히는 항목이다.

- [ ] 모델이 만든 HTML을 sanitize 없이 렌더링하지 않는다
- [ ] 모델이 만든 SQL·셸 명령을 그대로 실행하지 않는다. 실행한다면 **허용 목록 + 파라미터화**
- [ ] 모델 출력을 다른 시스템에 넘기기 전에 **스키마 검증**을 통과시킨다
- [ ] 모델이 만든 URL로 서버가 요청하지 않는다 (SSRF — A10)

### LLM06 Excessive Agency — CWE-250 · CWE-269

에이전트가 **필요 이상의 툴·권한·자율성**을 가진 경우다.

- [ ] 툴 목록이 그 작업에 필요한 최소다. "있으니까 준" 툴이 없다
- [ ] 각 툴의 권한이 **호출자 사용자 권한으로 제한**된다 (에이전트가 관리자 자격으로 돌지 않는다)
- [ ] 파괴적 툴(삭제·이체·발송·배포)에 사람 확인이 걸려 있다
- [ ] 대량 작업에 상한이 있다 (한 번에 처리할 레코드 수)
- [ ] 에이전트 행동이 **감사 가능하게 기록**된다 — 어떤 툴을 어떤 인자로 불렀는지 (A09)

### 나머지 항목

`LLM03`(모델·플러그인 공급망 — A06과 같은 축) · `LLM04`(학습/RAG 색인 오염) ·
`LLM07`(시스템 프롬프트 누출 — **비밀을 시스템 프롬프트에 두지 않는 것이 유일한 답**) ·
`LLM08`(임베딩 저장소의 접근 제어·교차 오염) · `LLM09`(오정보 — 사실로 제시되는 출력에
근거·불확실성 표시) · `LLM10`(무제한 소비 — 토큰·비용 상한, API4와 같은 축).
