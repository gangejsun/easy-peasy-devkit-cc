# Insight Saver

대화 중 중요한 인사이트, 교훈, 분석 결과를 구조화된 문서로 저장.

## 워크플로우

### Step 1: 컨텍스트 분석

최근 5-10개 메시지를 분석하여 핵심 정보 추출: 주제 식별, 카테고리 자동 추론, 핵심 인사이트 추출.

### Step 1.5: 저장 필요성 판정 — 만들지 않을 조건 먼저

아래 셋 중 하나면 **새 파일을 만들지 않는다.** 저장소에 이미 있는 것을 늘리는 건
기록이 아니라 소음이다:

| 조건 | 확인 방법 | 만들지 않고 하는 것 |
| --- | --- | --- |
| 동일 주제 인사이트가 이미 있음 | `grep -rli "<주제 핵심어 1~2개>" dev/docs/insights/ 2>/dev/null` | 기존 파일에 새 근거를 **추가 갱신**하겠다고 제안 |
| 사용자 수정/지적에서 나온 교훈 | 대화에서 사용자가 접근을 바로잡았는가 | `docs/lessons.md`에 lessons 카드 형식으로 기록 (그쪽 원장 담당) |
| 코드·문서에서 재도출 가능한 사실 | 저장소를 읽으면 알 수 있는 내용인가 | 저장하지 않음 — 근거를 1줄로 사용자에게 보고 |

### Step 2: 파일명 생성

형식: `{category}/{topic-slug}-{YYYY-MM-DD}.md`

### Step 3: 문서 작성

필수 구조 (이 4섹션이 없으면 Step 4.5 검증에서 실패한다):

```markdown
# {제목}

## 상황
{어떤 작업/논의에서 나왔는가 — 2~3줄}

## 인사이트
{핵심 결론 — 나중에 이것만 읽어도 되게}

## 근거
{왜 그렇게 판단했는가 — 파일·측정·사건}

## 적용
{다음에 언제 어떻게 쓰는가}
```

### Step 4: 파일 저장

경로: `dev/docs/insights/{category}/{filename}.md` (카테고리 디렉토리 자동 생성)

### Step 4.5: 저장 후 검증 — 실패 시 파일을 지운다

```bash
grep -c '^## 상황\|^## 인사이트\|^## 근거\|^## 적용' "dev/docs/insights/<경로>"
```

4가 아니면 파일을 삭제하고 실패 항목을 보고한다. 깨진 구조를 남기는 것보다
없는 게 낫다 — 다음 검색자가 신뢰할 수 없는 원장은 원장이 아니다.

### Step 5: 사용자 피드백

저장 경로 + Step 1.5 판정 결과(만들지 않았다면 그 근거)를 보고한다.

## 주의사항

- **동일 주제 파일이 이미 있으면 접미사로 새 파일을 만들지 않는다** — 중복은
  파일명 충돌 문제가 아니라 병합 신호다. 같은 주제 파일 3개는 검색을 3배 느리게 한다
- 파일명에 날짜 필수 포함
