# Research

주어진 주제에 대해 공개 웹 정보를 수집하고 구조화된 리서치 문서를 생성하는 스킬입니다.

## 한계

- 유료 보고서, 비공개 API, 인증 필요 서비스의 데이터 수집
- 실시간 가격/사용자 수 등 정확한 수치 보장
- 한국어 로컬 데이터의 완전한 커버리지

## 워크플로우

### Step 1: 리서치 유형 판별

| 유형        | 판별 키워드 |
| ----------- | ----------- |
| 경쟁사 분석 | 경쟁사, 경쟁 서비스, 대안 |
| 시장 조사   | 시장, 규모, 트렌드 |
| 기술 조사   | 기술, 비교, 라이브러리 |
| 사용자 조사 | 사용자, 니즈, 페인포인트 |
| 자유 주제   | 기타 |

유형이 곧 Step 5에서 쓸 템플릿을 정한다. 애매하면 사용자에게 하나 고르게 한다 —
유형 없이 수집하면 출처는 모이는데 문서가 조립되지 않는다.

### Step 2: 기존 리서치 확인 — 만들지 않을 조건

`dev/docs/research/`를 주제 키워드로 찾는다.

| 발견 | 행동 |
| --- | --- |
| 같은 주제, **90일 이내** | **새로 만들지 않는다.** 기존 문서를 제시하고 "갱신할 항목만" 물어본다 |
| 같은 주제, 90일 초과 | 기존 문서를 baseline으로 열고 변한 것만 재조사 (전면 재작성 아님) |
| 인접 주제만 있음 | 참조로 링크하고 신규 작성 |
| 없음 | 신규 작성 |

90일인 이유: 시장·가격·경쟁 서비스는 분기 단위로 움직이고, 그보다 짧게 잡으면
같은 문서를 계속 다시 쓰게 된다.

### Step 3: 사용자 데이터 확인

**웹에 나가기 전에 프로젝트 안을 먼저 본다.** 사용자가 이미 가진 데이터가 있으면
검색 결과보다 우선한다 (실측 > 공개 추정치):

- `dev/docs/` 의 기존 기획·PRD에 적힌 수치·타겟·경쟁사 목록
- 사용자가 대화에 붙여넣은 자료 · 지정한 파일
- 프로젝트 코드가 실제로 쓰는 라이브러리·서비스 (기술 조사일 때)

없으면 없다고 적고 넘어간다 — **여기서 묻는 것은 "가진 자료가 있는지" 하나다.**

### Step 4: 정보 수집

유형별 검색축 3~5개를 먼저 적고, 축마다 WebSearch를 돌린다. 축을 적지 않고 검색하면
첫 결과에 끌려간다.

| 유형 | 검색축 |
| --- | --- |
| 경쟁사 분석 | 서비스 목록 · 가격/플랜 · 사용자 평가 · **실패·철수 사례** |
| 시장 조사 | 시장 규모 출처 · 성장률 · 규제/제도 · 주요 플레이어 |
| 기술 조사 | 공식 문서 · 벤치마크 · 마이그레이션 후기 · **알려진 한계** |
| 사용자 조사 | 커뮤니티 불만 · 리뷰 · 대안 탐색 글 |

수집 상한: **축당 검색 최대 3회.** 3회로 축이 안 채워지면 그 축을 "자료 부족"으로
표시하고 넘어간다 — 무한 검색은 문서를 늦출 뿐 정확도를 올리지 않는다.

각 사실은 **URL + 게시 날짜**와 함께 적는다. 날짜를 확인할 수 없는 자료는 인용하되
"날짜 미상"으로 표시한다.

### Step 5: 구조화된 문서 생성

Step 1의 유형에 해당하는 템플릿을 `resources/research-templates.md`에서 읽어 그대로 채운다.
**템플릿에 없는 섹션을 추가하지 않는다** — 실행마다 구조가 달라지면 PRD가 이 문서를
그대로 받을 수 없다.

모든 유형은 공통 헤더 + 유형 본문 + 공통 푸터(데이터 출처 · 한계 · PRD 반영 제안)를 갖는다.

### Step 6: 파일 저장 및 사용자 확인

저장 경로: `dev/docs/research/<topic>.md`

저장 전 자체 검증 — 하나라도 실패하면 저장하지 않고 그 항목을 보고한다:

- [ ] 템플릿의 필수 섹션이 전부 있는가
- [ ] 인용한 수치마다 출처 URL이 붙어 있는가
- [ ] "자료 부족"으로 남은 축이 「한계」에 적혀 있는가

## 참조 문서

| 파일 | 언제 읽는가 |
| --- | --- |
| `resources/research-templates.md` | **Step 5에서만.** 유형이 정해진 뒤 해당 유형 절만 읽는다 (281줄 전체를 읽지 않는다) |
| `dev/docs/research/` | Step 2 — 기존 리서치 확인 |

## Pitfalls

- WebSearch 결과의 날짜를 반드시 확인 — 3년 전 가격표가 현재처럼 보인다
- 검색어 편향 방지 — "실패", "문제", "한계" 키워드도 검색한다
- 단일 출처의 수치를 "시장 규모"로 단정하지 말 것 — 출처가 하나면 그렇게 표시한다
