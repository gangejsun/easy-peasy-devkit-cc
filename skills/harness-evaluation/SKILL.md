# Harness(Graph) Evaluation

자산 단위("무엇이 있는가")가 아니라 **경로 단위**("작업 1건이 어떤 노드를 밟고,
어디서 멈추고, 무엇을 남기는가")로 평가한다. 점수는 내지 않는다 —
산출물은 **결함 목록**이고, 그 자체가 개선 백로그다.

## 5축

| 축 | 질문 | 기계 판정 (Step 1) | 모델 판단 (Step 2) |
| --- | --- | --- | --- |
| **P1 라우팅 일관성** | 모든 분기가 v3 어휘(되돌림 클래스·진입 조건 미충족 수)만 보는가 | S/M/L grep — 취약점 심각도 등급표(Critical/High/Medium/Low)는 오탐이므로 제외 | 위반이 실제 오동작을 만드는가 |
| **P2 발동 정확성** | ① 조건 충족 시 자동 발동하는가 ② 노드 권한 형태가 맞는가(검증자 읽기 전용 등) ③ 발동 시 잡아야 할 것을 잡는가 | 그래프 선언 대조 · 에이전트 frontmatter · `--self-test` 양성 픽스처 | 수동이 의도인가 누락인가 · 게이트 미탐 · handoff 복원 충분성 · 게이트가 전제하는 검증 기반(빌드/테스트 경로) 실재 |
| **P3 루프 종료성** | 반복 노드가 상한·종료 술어를 갖는가 | 상한 grep — **references/ 포함** (상한이 공유 파일에 있을 수 있다) | 상한이 작업 성격에 적정한가 |
| **P4 되먹임 폐쇄성** | 기록이 자산 diff로 돌아오는가 | `--lessons` + 저장소 3계(lessons·insights·memory) 승격 경로 유무 | 승격 형태(훅/스킬/규칙) 선택이 옳은가 |
| **P5 경로 비용** | 클래스별 대표 작업 1건의 노드 수·게이트 수가 적정한가 | `--usage` (graph.log·skilluse.log 집계) | Reversible 경로의 과잉 게이트 · 상주 컨텍스트 과잉 |

**네이티브 중복·모델 과잉 점검**은 독립 축이 아니라 P2·P5의 판단 입력이다.
판정에는 시점 스탬프("Claude Code 버전 · 모델 · 날짜")를 반드시 남기고, 직전
스탬프가 30일 이내면 재조사를 생략한다. 커스텀 폐기를 제안하려면 **양쪽 본문을
실제로 열어** 커버 영역을 비교해야 한다 — 네이티브의 존재는 중복의 증거이지
열등의 증거가 아니다.

## 워크플로우

### Step 1: 기계 판정 수집 — 다시 세지 않는다

```bash
bash "${CLAUDE_PLUGIN_ROOT:-.}/scripts/doctor.sh" --all
# P1 — 라우팅 어휘 (심각도 등급표 문맥은 제외하고 해석)
grep -rn 'Small\|Medium\|Large' skills/*/SKILL.md
# P3 — 반복 상한 (공유 파일 포함)
grep -rln '최대 [0-9]회\|1회 재' skills/*/SKILL.md skills/*/references/*.md
# P4 — 기록 저장소 3계 실재
ls docs/lessons.md dev/docs/insights memory/ 2>/dev/null
```

### Step 2: 5축 판정 + 결함 목록

- 축마다 두 줄로 판정한다: `측정: <기계 출력 요약>` / `판정: <충족|미달> — <근거>`
- 결함은 `ID | 심각도 | 파일:행 | 실패 시나리오 | 수정 방향` 형식.
  심각도는 epcc-reviewer와 동일 어휘(Critical/Important/Suggestion).
  **실패 시나리오를 쓸 수 없으면 그 결함은 보고하지 않는다** — "~일 수 있다"는 추측이다.
- **grep·doctor에 걸리지 않은 문서를 읽으러 가지 않는다.** 전 문서 독해는 폐기된 방식이다.
- 전회 판정을 계승하지 않는다 — 반드시 현재 파일로 재확인한다.

### Step 3: 저장 + 전회 대비

1. 형식: `assets/report-template.md`
2. 버전: `ls dev/docs/harness-evaluation/`의 최대 vN에 +1 (**파일명이 원장이다** — 별도 기록 없음)
3. 저장: `dev/docs/harness-evaluation/v{N}.md`
4. 전회가 있으면 결함 증감만 요약한다 ("Critical 2→0" 형식). 점수 추세는 없다.

## 부록: 커버리지 맵 (v2 10축 → 5축)

축 개편 시 이 맵의 갱신이 의무다. **행선지가 빈 항목이 생기면 개편은 미완성이다.**

| 구축 (v2) | 행선지 |
| --- | --- |
| 1 진입 규율 | P5 (과잉 서류) + P2-① (미발동) |
| 2 토큰 효율 | P5 |
| 3 확인 편향 방지 | P2-①② (발동 + 권한 독립) |
| 4 컨텍스트 연속성 | P4 + P2-③ (handoff 복원 충분성) |
| 5 점진적 거버넌스 | P1 + P5 |
| 6 자기 개선 | P4 |
| 7 보안 | P2-③ (양성 픽스처가 기계 판정) |
| 8 네이티브 중복 | P2·P5 판단 입력 (시점 스탬프) |
| 9 SW 기반 | P2-③ 전제조건 (게이트가 의존하는 검증 기반 실재) |
| 10 모델 과잉 | P5 판단 입력 (시점 스탬프) |
