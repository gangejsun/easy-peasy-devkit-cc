# Skill Enhancer

스킬을 **고립된 산출물**에서 **그래프의 노드**로 승격시킨다.
6패턴의 정의·실증·주입 방법과 겹침 판정 절차는 `references/superiority-patterns.md`가
원본이다 — Step 0 판정 전에 반드시 읽는다.

> **경계**: 생성·테스트 프롬프트·A/B 벤치마크는 skill-creator의 영역이다.
> 이 스킬은 그 평가 루프가 채점하지 못하는 차원 — 실패했을 때의 행동,
> 이웃 도구와의 분업, 토큰 규율 — 만 다룬다. 겹치지 않고 이어진다.

## Step 0: 존치 판정 — 강화 앞에 선다

**없어질 스킬을 강화하는 것이 가장 비싼 결과다.** description은 그 스킬을 한 번도
호출하지 않아도 매 세션 상주하므로, 존재 자체가 영구 비용이다. `rules/harness-change.md`의
Q1~Q3은 **추가 전** 게이트라 기존 스킬에는 한 번도 다시 던져지지 않았다. 여기서 던진다:

| # | 질문 | YES면 |
| --- | --- | --- |
| Q1 | 기존 스킬·훅·**네이티브 빌트인**과 역할이 겹치는가 | 아래 「겹침 판정」으로 |
| Q2 | 모델 성능이 좋아져서 이제 불필요한 것 아닌가 | **삭제** 후보 |
| Q3 | 이미 잘 동작하는데 굳이 바꾸는 것 아닌가 | **존치**(무변경) — 여기서 끝낸다 |
| Q4 | 라우팅 카드·그래프에서 도달 가능한가 | NO면 **수동 전환** 또는 배선 누락 |

판정은 다섯이고, **되돌림 클래스가 실행자를 정한다**:

| 판정 | 실행 | 클래스 |
| --- | --- | --- |
| **존치** | Step 1로 진행 (= 강화) | Reversible |
| **수동 전환** | `disable-model-invocation: true` — 본문 유지, description만 비상주화 | Reversible |
| **경계 분할** | 합치지 않고 양쪽 description에 P1 경계 선언 | Reversible |
| **합병** | 둘을 하나로 + 한쪽 제거 + 라우팅·그래프 엣지 이설 | **Costly — 사용자 확인** |
| **삭제** | 스킬 제거 + 라우팅·그래프·프리셋에서 제외 | **Costly — 사용자 확인** |

기계로 먼저 좁힌다:

```bash
# Q4 — 라우팅·그래프 도달성 (둘 다 0이면 수동 전환 후보)
grep -c "\`/<대상>\`" .claude/rules/workflow-routing.md "${CLAUDE_PLUGIN_ROOT:-.}/rules/workflow-routing.md" 2>/dev/null
jq --arg n "<대상>" '[.edges[] | select(.to == $n)] | length' "${CLAUDE_PLUGIN_ROOT:-.}/workflow.graph.json"
# 상주 비용 — 이 스킬이 매 세션 무는 바이트
awk '/^---$/{n++;next} n==1 && /^(name|description):/{p=1} n==1 && /^[a-z_-]+:/ && !/^(name|description):/{p=0} n==1&&p{print} n>=2{exit}' <대상>/SKILL.md | wc -c
```

**존치 외 판정이 나오면 Step 1로 내려가지 않는다.** 판정과 근거만 보고하고 멈춘다 —
합병·삭제는 소비자에게 즉시 전파되므로 사용자가 고른다.

### 겹침 판정 — 우위 보존이 결론을 정한다

"겹친다"는 관측이지 판정이 아니다. 먼저 **양쪽의 우위를 목록으로 추출**한 뒤 순서대로 묻는다.
순서를 뒤집으면 우위가 있는 쪽이 먼저 지워진다.

1. A의 우위가 B에 **전부 포함**되는가 → YES면 **흡수**(A 제거). 실제로는 드물다.
2. 양쪽 우위가 **서로 다른 상황**에서 쓰이는가 → YES면 **경계 분할**. ← 기본값
3. 둘 다 아니면 **합병** — 단 아래 의무를 지킨다.

**②가 기본값인 이유는 비용 비대칭이다.** 합병이 틀리면 잃는 것은 우위이고 되돌리기 어렵다.
합치지 않아서 무는 비용은 description 한 줄씩(작고 예산에 여유가 있다).

**합병의 의무**: 실행 전에 **우위 대조표**(추출 항목 × 합본 보유 여부)를 만들고, 한 항목이라도
옮겨지지 않으면 합병하지 않는다. "합쳐보고 판단"은 안 된다 — 그때는 이미 한쪽이 지워져 있다.

**경계 분할의 실행**은 둘 다 남기는 것으로 끝나지 않는다. 겹침 구간을 문장으로 배정해
없애는 것까지가 한 동작이다 — 절차는 카탈로그 P1의 「겹침 구간을 없애는 4단계」에 있다.

## Step 1: 뺄셈 — 기계 판정 먼저

강화 전에 먼저 뺀다. 아래 넷은 **전부 기계로 판정된다** — 모델 판단으로 두었더니
저장소에 빈 절 16건이 살아남았다:

```bash
# 빈 절 제목 (제목만 있고 본문 없이 같거나 얕은 레벨 제목이 뒤따름)
awk '/^```/{f=!f;prev="";next} f{next} /^#+ /{l=index($0," ")-1; if(l>=2&&prev!=""&&l<=pl) print "EMPTY: "prev; prev=(l>=2?$0:""); pl=l; next} NF{prev=""}' <대상>/SKILL.md
# 근거 없는 강제 어휘 — 대문자 MUST만 보면 MANDATORY·Iron Law 계열을 통째로 놓친다
grep -nE 'MUST|ALWAYS|NEVER|MANDATORY|Iron Law|No exceptions|반드시|절대' <대상>/SKILL.md
# Pitfalls가 Step 시퀀스를 끊는가 (읽는 순서와 실행 순서가 어긋난다)
grep -nE '^#{2,3} .*(Pitfalls|주의)|^### Step' <대상>/SKILL.md
# 고아 리소스 · description이 약속했는데 본문에 없는 것
bash "${CLAUDE_PLUGIN_ROOT:-.}/scripts/doctor.sh" --fast 2>&1 | grep -E '고아 리소스|빈 절 제목'
```

강제 어휘는 **지우는 것이 기본이 아니다** — 이유를 붙이거나, 그 이유가 T0 규범·훅에 이미
있으면 중복이므로 뺀다. 뺄 것이 있으면 목록을 보이고 확인 후 제거한다.

## Step 2: 6패턴 진단 — 기계 판정 먼저

카탈로그를 읽은 뒤, 기계로 판정 가능한 것부터 실행한다 (`<대상>` = 스킬 디렉토리):

```bash
# P3 — 반복 상한 부재 (반복·재시도 언급이 있는데 상한이 없으면 미달)
grep -nE '반복|재시도|다시|until|retry' <대상>/SKILL.md | grep -vcE '최대 [0-9]|상한'
# P4 — 판단 단계에 기계 명령 부재 (코드블록 수 대비 Step 수)
grep -c '^### Step' <대상>/SKILL.md; grep -c '^```' <대상>/SKILL.md
# P5 — 라우팅 변수 위반 (심각도 등급표 문맥은 오탐 — 제외하고 해석)
grep -nE 'Small|Medium|Large' <대상>/SKILL.md
# P6 — 리소스 시점 안내 부재
ls <대상>/references <대상>/resources 2>/dev/null; grep -c '언제 읽' <대상>/SKILL.md
```

기계 판정 결과 위에 모델 판단을 얹는다: 카탈로그의 **적용 조건 매트릭스**로
스킬 유형을 정하고, 해당 유형에 "필수"인 패턴의 충족 여부만 깊게 본다.
**매트릭스에 없는 패턴을 발명하지 않는다.**

## Step 3: 강화 적용 — 해당되는 것만

진단에서 미달로 판정된 패턴만, 카탈로그의 "주입 방법"에 따라 적용한다.

- 각 주입은 **대상 스킬의 어휘와 문체**를 따른다 (강화가 이식 티를 내면 안 된다)
- P3의 상한 숫자, P2의 금지 문구는 **그 스킬의 작업 성격에서 도출**한다 — 카탈로그
  예시를 복사하지 않는다
- 적용하지 않은 패턴은 "해당 없음 — 근거"로 기록한다 (침묵 생략 금지)

## Step 4: 자기 검증 — 실패 시 되돌린다

- [ ] 강화 후에도 description의 모든 약속이 본문에 실재하는가
- [ ] 새로 넣은 반복 상한·강등 규칙·금지 문구에 각각 이유가 붙어 있는가
- [ ] Step 1의 네 명령이 전부 0건인가 (뺀 것이 다시 들어오지 않았는가)
- [ ] 줄 수: 강화 후 SKILL.md ≤ 300줄 (넘으면 리소스로 분리하거나 뺄셈 재수행)
- [ ] **description 바이트 귀속**: 순증이 있으면 그 증가분이 P1 경계 또는 P5 호출 계약으로
      설명되는가. 설명되지 않는 순증은 되돌린다 — P1·P5는 구조적으로 description을
      늘리는데 그 비용은 매 세션 무조건 나간다

```bash
awk '/^---$/{n++;next} n==1 && /^(name|description):/{p=1} n==1 && /^[a-z_-]+:/ && !/^(name|description):/{p=0} n==1&&p{print} n>=2{exit}' <대상>/SKILL.md | wc -c
```

- [ ] doctor가 있으면(플러그인 또는 저장소): `bash "${CLAUDE_PLUGIN_ROOT:-.}/scripts/doctor.sh" --default` 통과
- [ ] 그래프 파일이 있으면: 노드/엣지 추가 후 `--graph` 통과

하나라도 실패하면 해당 주입을 되돌리고 실패 항목을 보고한다.

## Step 5: 보고 + description 인계

- Step 0 판정과 근거 (존치가 아니면 여기서 보고가 끝난다)
- 패턴별 결과 표: `패턴 | 진단 | 적용/해당 없음 | 변경 위치`
- 강화 diff 요약: 추가 N줄 / **삭제 N줄** (뺄셈이 0이면 Step 1을 건너뛴 것이다) /
  **description 전 N바이트 → 후 N바이트**

### description은 skill-creator에게 넘긴다 — 순서가 정해져 있다

skill-creator의 마지막 단계인 Description Optimization(`run_loop.py` → `best_description`)과
이 스킬의 P1·P5는 **같은 필드에 쓴다.** 나중에 도는 쪽이 조용히 이긴다. 순서는 하나다:

**강화의 description 주입이 먼저, optimizer가 나중.** 그리고 optimizer에 넘기는 eval set에
**P1 경계가 만든 near-miss를 should-not-trigger로 반드시 포함한다** — 넣지 않으면
최적화가 경계 문장을 지우고도 점수가 오른 것처럼 보인다.

행동 변화가 큰 강화(P2·P3)는 **skill-creator의 평가 루프로 전/후 A/B 검증을 권한다** —
강화가 실제로 이겼는지는 실측만이 증명한다. 이때 baseline은 강화 전 스냅샷이다.
