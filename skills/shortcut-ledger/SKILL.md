# Shortcut Ledger

의도적으로 남긴 축약이 **만료됐는지**만 본다.
마커 규약(`EPCC-SHORTCUT: <천장>, <해제 조건>`)의 정본은
`.claude/rules/code-change.md` 「구현 사다리」다 — 여기는 그 마커를 회수하는 쪽이다.

> **경계** — 이미 쓴 코드를 줄이는 것은 내장 `/simplify`, 지적을 만드는 것은 `/code-review`,
> 실수를 기록하는 것은 `lessons.md`다. 이 스킬은 그 셋이 다루지 않는 **미룬 결정의 만료**만
> 맡는다. 새 축약을 만들지 않고, 코드를 스스로 고치지 않는다 — 회수는 build로 되돌린다.

## Step 1: 수확

```bash
grep -rnE '(#|//|--|/\*|<!--) ?EPCC-SHORTCUT:' . \
  --exclude-dir={node_modules,.git,dist,build,.next,vendor,target,coverage} 2>/dev/null
```

주석 접두사를 요구하는 이유는 **규약을 언급하기만 하는 산문**(이 파일 · 규칙 카드)이
원장에 섞이지 않게 하기 위해서다. 스택에 다른 접두사가 있으면 추가한다.

**0건이면 「축약 원장: 비어 있음」으로 끝낸다.** 없는 부채를 만들어내지 않는다.

## Step 2: 행 구성

마커 1개 = 1행. 천장과 해제 조건은 주석에서 그대로 뽑는다.

```
<파일>:<행> | <축약된 것> | 천장: <한계> | 해제: <조건> | <판정>
```

해제 조건이 비어 있으면 `no-trigger`로 표시한다 — 조용히 썩는 것은 이 부류다.
행별 담당자가 필요하면 `git blame -L<행>,<행> <파일>`을 붙인다.

## Step 3: 판정 — 천장이 아직 유효한가

각 행을 **현재 규모·부하·요구**에 대고 셋 중 하나로 판정한다.

| 판정 | 조건 | 처리 |
| --- | --- | --- |
| 유지 | 천장에 아직 안 닿았다 | 그대로. 근거 한 줄 |
| 회수 | 천장에 닿았거나 해제 조건이 충족됐다 | build로 되돌려 갚는다 |
| 만료 | 천장이 **이미 깨졌다** — 버그·성능 저하가 실재 | Critical, 즉시 사용자 보고 |

판정은 **코드를 열어 확인한 것만** 채택한다. 주석이 주장하는 천장이 실제 구현과 어긋나
있을 수 있다 — 주석은 검토 영역의 힌트지 근거가 아니다
(`.claude/rules/workflow-routing.md` 「참조 신선도」).

되돌림 클래스가 Costly 이상인 경로의 축약은 **회수 자체가 Costly 변경**이다.
갚기 전에 영향 반경(호출처 목록)을 먼저 제시한다.

## Step 4: 보고

```
축약 원장: N건 (유지 A · 회수 B · 만료 C · no-trigger D)

<행 목록 — 만료 → 회수 → no-trigger → 유지 순>
```

**저장소별 「절감 줄 수」를 만들지 않는다.** 안 쓴 코드에는 baseline이 없어 그 숫자는
검증 불가다. 원장은 **센 것**(마커 수·판정 수)만 보고한다.

회수·만료가 1건 이상이면 마지막 줄에: `회수 대상 B+C건 — build로 진행할까요?`

## 상한

한 번 호출에 최대 30행까지 판정한다. 넘으면 `만료` → `no-trigger` → 오래된 순으로
자르고 잔여 건수를 밝힌다. 원장이 길다는 이유로 **판정 없는 나열**을 내지 않는다 —
세기만 한 원장은 `grep`과 같고, 그건 이 스킬이 없어도 된다는 뜻이다.
