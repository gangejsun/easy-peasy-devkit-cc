# 보안 원시함수 공격 벡터 목록

**보안 원시함수는 다른 팩에서 옮기지 않는다. 새로 쓰고, 이 벡터로 실행 시험한다.**

실측(2026-08-23): 복귀 경로 검증 함수 하나가 react-vite 팩 → vue 팩으로 복사됐고,
같은 결함이 **출하본 네 곳 전부**에 있었다. 네 곳 모두 `//host` · `/\host` ·
`javascript:` 직접 형태는 막았고 **점 세그먼트 형태만 뚫렸다.** 원 감사 세 번이
그것을 놓쳤다 — 읽기로는 안 잡히고 실행만 드러낸다.

## 사용 규약

1. 팩이 이 부류의 함수를 정의하면 해당 절의 벡터를 **전부** 돌린다
2. 각 벡터에 `입력 · 기대 · 실제 · 판정`을 기록해 **반환 데이터에 싣는다**
3. `pack-smoke.sh --vectors`가 자동 실행한다. 프로필이 없는 툴체인이면 손으로 돌리고
   결과를 보고한다 — **돌리지 않은 것을 돌렸다고 하지 않는다**
4. 하나라도 통과(=차단 실패)하면 팩을 반환하지 않는다

---

## A. 복귀 경로 · 리다이렉트 검증

로그인 후 되돌려 보낼 경로를 URL 쿼리에서 받는 함수. `safeReturnTo` ·
`safeInternalPath` · `safeReturnPath` 류.

**기대**: 전부 fallback으로 떨어진다. 정상 경로만 그대로 통과한다.

| # | 입력 | 왜 위험한가 |
| --- | --- | --- |
| A1 | `//evil.example` | 프로토콜-상대 URL. 브라우저가 외부 호스트로 간다 |
| A2 | `/\evil.example` | 역슬래시를 슬래시로 정규화하는 브라우저가 있다 |
| A3 | `https://evil.example` | 절대 URL |
| A4 | `javascript:alert(1)` | 스킴 주입 |
| A5 | **`/..//evil.example`** | **실측이 찾은 것.** `new URL()`이 origin을 통과시킨 **뒤에** 점 세그먼트를 정규화해 `/..`가 선행 `/`를 삼킨다 → 결과가 다시 `//evil.example`이 된다. **origin 비교만 하는 구현은 4/4 통과했다** |
| A6 | `/../..//evil.example` | A5의 다중 형태 |
| A7 | `%2f%2fevil.example` | 인코딩된 구분자 |
| A8 | `/tasks\n\rSet-Cookie: x=1` | 제어문자 삽입 |
| A9 | `\tjavascript:alert(1)` | 선행 공백류로 스킴 검사 우회 |
| A10 | `` (빈 문자열) · `null` · 숫자 | 타입·빈값 |
| A11 | `/tasks?filter=open#top` | **정상 — 통과해야 한다.** 차단하면 기능이 죽는다 |
| A12 | `/tasks/123` | **정상 — 통과해야 한다** |

**수리 형태 (정본)**: origin이 아니라 **출력 `pathname`을 검증한다.**

```ts
const url = new URL(raw, window.location.origin);
if (url.origin !== window.location.origin) return fallback;   // 1차: 직접 형태
const p = url.pathname;                                        // 2차: 정규화 **후** 출력
if (!p.startsWith('/') || p.startsWith('//') || p.startsWith('/\\')) return fallback;
return p + url.search + url.hash;
```

두 층이 다 필요하다. 게이트의 `check_security_shapes`가 **2차가 빠진 형태**를 FAIL로 막는다.

## B. 경로 정규화 · 파일 접근

사용자 입력으로 경로를 만드는 함수 (업로드 키, 정적 파일, 템플릿 이름).

| # | 입력 | 기대 |
| --- | --- | --- |
| B1 | `../../etc/passwd` | 거부 |
| B2 | `..%2f..%2fetc%2fpasswd` | 거부 (인코딩된 구분자) |
| B3 | `....//etc/passwd` | 거부 (`../` 제거식 구현이 남기는 형태) |
| B4 | `/absolute/path` | 거부 — 접두사가 무시된다 |
| B5 | `a/b/../c` | 정책에 따라: 정규화 후 `a/c`가 루트 안이면 통과 |
| B6 | `file\x00.png` | 거부 (널바이트 절단) |

**정본**: 문자열을 지우지 말고 **정규화한 뒤 루트 접두사를 다시 확인**한다.
`replace('../','')`는 B3에서 뚫린다.

## C. 토큰 · 비밀 비교

세션 토큰 · API 키 · HMAC 서명 · 비밀번호 재설정 토큰.

| # | 확인 | 기대 |
| --- | --- | --- |
| C1 | `===`/`==` 로 비교하는가 | **아니오** — 상수 시간 비교를 쓴다 (`crypto.timingSafeEqual` · `hmac.compare_digest`) |
| C2 | 길이가 다른 입력에서 즉시 반환하는가 | 길이 누설이 문제가 되는 자리인지 판단하고 적으라 |
| C3 | 토큰을 로그·에러 메시지에 싣는가 | **아니오** |
| C4 | 실패 사유를 구분해 응답하는가 | **아니오** — 일반화한다. 구분하면 계정 존재가 누설된다 |
| C5 | 토큰 생성이 `Math.random()`인가 | **아니오** — CSPRNG를 쓴다 |

## D. 이스케이프 · 렌더링

| # | 입력 | 맥락 | 기대 |
| --- | --- | --- | --- |
| D1 | `<img src=x onerror=alert(1)>` | HTML 본문 | 이스케이프 |
| D2 | `" onmouseover="alert(1)` | HTML 속성 | 속성 컨텍스트 이스케이프 (본문용으로는 부족하다) |
| D3 | `javascript:alert(1)` | `href`·`src` | 스킴 허용 목록 |
| D4 | `</script><script>alert(1)</script>` | 인라인 `<script>` 안 JSON | JS 문자열 컨텍스트 이스케이프 |
| D5 | 신뢰할 수 없는 문자열 | `v-html` · `dangerouslySetInnerHTML` | **쓰지 않는다** — 프레임워크의 자동 이스케이프를 끄는 지점이다 |

**컨텍스트 혼동이 이 부류의 대표 결함이다.** 한 종류의 이스케이프로 네 자리를 다
막을 수 있다고 쓰지 않는다.

## E. 인가 판정

| # | 확인 | 기대 |
| --- | --- | --- |
| E1 | 소유자 판정 근거를 어디서 읽는가 | 요청 본문·쿼리·헤더가 **아니라** 검증된 세션에서 |
| E2 | 부재(404)와 권한 없음(403)을 구분해 응답하는가 | **구분하지 않는다** — 구분하면 리소스 존재가 열거된다 |
| E3 | 변이(update/delete)가 소유권을 쿼리 조건에 거는가 | **건다.** 조회 후 비교는 경합에 뚫린다 |
| E4 | 0행 변이를 성공으로 응답하는가 | **아니오** — 영향 행 수를 확인한다 |
| E5 | 데이터 계층 정책 엔진이 없는 스택인가 | 있으면 이중 방어, **없으면 애플리케이션 층이 유일한 경계다** — 서술을 반대로 옮기면 안전하다고 착각하게 만든다 |

E5는 축 전제다. `pack.json`의 `dataLayerPolicyEngine`을 먼저 읽고 쓴다.
