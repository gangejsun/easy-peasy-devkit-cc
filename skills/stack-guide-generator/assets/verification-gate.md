# Step 4 · 4-1: 기계 검증 게이트와 실행 검증

생성자도 반환 전에 같은 게이트를 돌리지만 **돌렸다는 보고 자체가 자기보고다** (원칙 5).

축 팩을 저작했다면 **조립 전에 `--pack`으로 먼저** 검사한다 (Step 2-A의 팬인 지점).
축 안에서 닫히는 검사만 돌리고 조합의 함수인 것(`requires` 충족 · `--pair` ·
대상=seam 정책)은 건너뛴 것을 명시 보고한다.

```bash
bash ${CLAUDE_SKILL_DIR}/scripts/guide-gate.sh --pack <팩경로> --claims-out <TSV경로>
```

`--claims-out`은 버전 주장 인벤토리를 파일로 내보낸다. **감사 B의 입력 전부**이고, 게이트의
임시 디렉토리는 종료 시 지워지므로 이것 없이는 40건 초과분이 사라진다.

조립본에는 아래를 돌린다.

```bash
bash ${CLAUDE_SKILL_DIR}/scripts/guide-gate.sh --guide <가이드경로> --generated \
  --pm <패키지매니저> --ledger <생성자가 반환한 원장> --forbid <확정 조합에 없는 스택 키워드> \
  --assembly <가이드경로>/assembly.json      # 팩을 조립한 축에서만 — 아래 참조
# 두 가이드를 만들었으면 계약 정합도 — 한쪽만 읽는 감사는 이 어긋남을 못 잡는다
bash ${CLAUDE_SKILL_DIR}/scripts/guide-gate.sh --pair --contract <Step 3-0의 계약 파일> \
  --frontend <프론트 경로> --backend <백엔드 경로>
```

**`--assembly`를 빼먹으면 팩 경계 검사가 통째로 꺼진다.** `install-guide.sh`가 남긴
`assembly.json`을 주면 두 검사가 켜진다:

| 검사 | 잡는 것 |
| --- | --- |
| 팩 인터페이스 | 팩의 `requires`를 이음매가 정의하지 않음 → 팩 예제가 실행 불가 |
| 정책 원장 | 팩이 선언한 파일 간 불변식을 이음매가 어김 (**실측 감사 57건 중 26건이 이 부류**) |

**게이트가 소유하게 된 것 (v3.13.0)** — 프롬프트나 사람의 기억에 있던 것을 옮겼다:

| 검사 | 대체한 것 |
| --- | --- |
| 정책 표의 `증명 예` 열 단언 | "정책마다 결함 픽스처를 만들어 잡히는지 돌리기" — **vue 저작의 벽시계를 지배했다.** 이제 밀리초에 단언한다 |
| `check_security_shapes` | 오픈 리다이렉트의 두 재발 형태. 팩별 정책이 아니라 축 무관 형태이므로 게이트 본체가 소유한다 |
| `check_claims` | 감사자에게 넘길 "버전 주장 목록"을 손으로 모으던 일. WARN + 인벤토리로 전수 수집한다 |
| `check_duplicate_fences` | 병렬 저작이 만드는 중복 서술. 원장은 심볼만 보고 서술은 보지 않는다 (REVIEW) |
| `fixesVariants` ↔ `pkgs` 정합 | 팩이 못박은 변형을 선언하지 않아 조립 시점에 대조할 수 없던 것 |
| `provides` 「형태」 열 강제 + 인자 개수 대조 | **치명 결함 2건의 단일 원인.** 소유 파일만 배정하면 형제 클러스터가 시그니처를 추측한다 |
| `check_blocking_proof` | 「차단 장치」로 제시된 테스트가 부정 단언만 걸어 구현을 통째로 실패시켜도 통과하던 것 (REVIEW) |
| `--self-test`의 **사전 제작 이음매 회귀** | 조합 단위 출하 자산이라 팩을 고칠 때마다 함께 검사해야 한다 — 조립해서 조립본 게이트와 `--pair`를 돌린다. `--pack`만으로는 `requires` 충족·대상=seam 정책이 켜지지 않는다 |
| `--self-test`의 **출하 팩 회귀 코퍼스** | 합성 픽스처는 **오탐을 못 잡는다.** 이 게이트의 결함 4건이 전부 실사용에서만 드러났다 — 이제 새 검사가 실물에 오탐하면 자기검사가 즉시 빨개진다 |

정책 검사는 `codelines()` 출력에만 걸린다 — 산문·주석·안티패턴 예시를 세면 전부
위양성이다 (개발 중 8건 확인). 정규식이 위양성을 내면 고칠 것은 코드가 아니라
**팩의 `policies.md`**다: 예외 파일을 지정하거나 정규식을 좁힌다.

**FAIL이 하나라도 있으면 설치하지 않는다** — 실패 항목을 서브에이전트에 돌려보내 수리시키고
다시 실행한다. WARN은 Step 7 보고에 싣는다. REVIEW는 **항목마다 정당화하거나 수리한다**:
기계가 판정할 수 없는 자리이므로 침묵 통과가 곧 결함 통과다.

### Step 4-1: 실행 검증 — 읽어서 안 잡히는 부류가 있다

**실측(2026-08-23)에서 기계 게이트 전항을 통과한 뒤 남은 결함은 거의 전부 실행으로
잡혔다.** 감사자가 스크래치에 실제 프로젝트를 만들어 vue-tsc·node를 돌려 찾았다 —
오픈 리다이렉트 · `:key` 재마운트 · msw import 누락 · 테스트 하네스의 스프레드 ·
`defineConfig`의 `test` 키. 그 자발적 행위를 파이프라인의 단계로 올린다.

```bash
bash ${CLAUDE_SKILL_DIR}/scripts/pack-smoke.sh --pack <팩경로> --keep --online
```

**`--online`이 타입체크를 감사 A에서 이 단계로 옮긴다.** 없으면 `tsc`가 skip으로 남고
감사 A의 첫 일이 npm 설치가 되어 그 대기가 감사 임계 경로에 얹힌다. `--online`은
`pack.json`의 `pkgs`를 **메이저 고정**으로 설치한다 — `npm i typescript`를 그냥 치면
오늘은 7.x가 깔리는데 팩이 확정한 것은 5다. 네트워크가 없으면 **skip 명시 보고**이지
FAIL이 아니다(오프라인 가용성은 이 스크립트의 전제다).

| 하는 일 | 비고 |
| --- | --- |
| `<!-- file: 경로 -->`로 **완전 파일을 주장한 펜스**만 실파일로 복원 | 발췌를 전부 컴파일시키려 하면 위양성 늪이 된다. 주장은 저자의 opt-in이다 |
| 원장 `requires`의 미해소 import를 스텁으로 채움 | 팩만 놓고 보면 이음매 심볼은 항상 미해소다 |
| 구문 검사 (`node`의 타입 스트리핑 — 오프라인) | JSX·SFC는 스트리핑 대상이 아니라 **미검사로 명시 보고**한다 |
| 타입체크 (`tsc`) | `--online`이면 팩이 못박은 메이저로 설치해 돌린다. 없으면 **skip을 명시 보고**한다 — 미검사이지 통과가 아니다 |
| `assets/security-vectors.md`의 복귀 경로 벡터 12건 실행 | **실측 최대 발견이 이 부류였다.** 차단 10 · 정상 통과 2를 모두 확인한다 |

`--keep`으로 남긴 작업 디렉토리와 `vector-report.tsv`를 **감사 A에 그대로 넘긴다** —
감사자가 스크래치 프로젝트를 처음부터 만드는 비용의 상당 부분이 여기서 이미 끝나 있다.

툴체인 프로필은 `scripts/profiles/<이름>.sh`다. 현재 **`node-ts`와 `python`** 둘이고,
복원 단위의 확장자로 자동 선택된다. 프로필이 없는 툴체인은 스크립트가 skip을 명시
보고한다 — 침묵 생략은 금지다.

**타입체커를 돌리려면 `pkgs`에 넣어야 한다.** `--online`은 `pkgs`만 설치하므로,
`typescript@N`이 없으면 tsc가, `pyright@N`·`mypy@N`이 없으면 파이썬 타입체크가
skip으로 남는다 — 그 skip은 통과가 아니라 **미검사**다.

#### 스키마 실행 (검증 라이브러리를 고정한 가이드)

실측 최악의 결함은 `partial()`과 `default()`를 겹쳐 **부분 업데이트가 보내지 않은 필드를
기본값으로 덮어쓰는** 스키마였다 — 문법은 완벽했고 실행만이 드러냈다. 가이드가 검증
라이브러리를 고정했다면 스크래치에 그것만 설치해 스키마 코드펜스를 파싱시킨다:

| 입력 | 확인할 것 |
| --- | --- |
| 빈 객체 | 필수 필드가 실제로 거부되는가 |
| 필드 1개만 담은 부분 업데이트 | **나머지 필드가 조용히 채워지지 않는가** |
| 미지 키 포함 | 통과·제거·거부 중 무엇인가 — 가이드의 서술과 같은가 |

결과가 가이드의 서술과 다르면 고칠 것은 스키마가 아니라 **그 서술**이다.
