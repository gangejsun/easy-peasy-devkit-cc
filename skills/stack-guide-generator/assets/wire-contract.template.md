# 와이어 계약 (Wire Contract)

<!-- epcc-wire-contract -->

두 가이드를 **격리** 생성할 때 양쪽 에이전트에 **토씨까지 동일하게** 붙여넣는 정본이다.
메인 세션이 Step 3-0에서 이 양식을 채워 스크래치 파일 1개로 만들고, Step 4에서
`guide-gate.sh --pair --contract <이 파일>`이 같은 파일로 양쪽을 대조한다.

> **채우는 규칙**: 필드 이름·에러 코드는 **각각 백틱으로** 감싼다
> (`` `nextCursor` ``, `` `NOT_FOUND` ``). 봉투를 통째로 하나의 백틱 스팬에 넣으면
> 게이트가 뽑을 토큰이 없어 대조가 조용히 통과한다. 상태 코드는 숫자 그대로 쓴다.
> 미결정 항목을 `<...>`로 남기면 게이트가 그 자리에서 FAIL로 잡는다.

## 1. 성공 응답 봉투

- 단건: `data` 하나만 담는다 — <예: `{ data: Note }`>
- 목록: <필드 이름을 각각 백틱으로 — 예: `data` 배열 + `nextCursor`>
- 삭제: <상태 코드와 본문 유무 — 예: 204, 본문 없음>

## 2. 에러 응답 봉투

<필드 이름을 각각 백틱으로 — 예: `error` 안에 `code`·`message`·`details`(선택),
최상위에 `requestId`>

## 3. 페이지네이션 모델

- 모델: <cursor 또는 offset — **하나만**. 둘을 섞으면 프론트의 목록 화면이 통째로 어긋난다>
- 요청 파라미터: <예: `limit`, `cursor`>
- 응답 필드: <예: `nextCursor` (마지막 페이지에서 null)>

## 4. 에러 코드 ↔ 상태 매핑

프론트가 `code`로 화면을 분기하면 이 표가 **양쪽에 그대로** 있어야 한다.
클라이언트가 스스로 만드는 코드(네트워크 실패 등)는 프론트 가이드에만 둔다.

| code | status | 언제 |
| --- | --- | --- |
| `<CODE>` | <상태> | <조건> |

## 5. 인가 실패의 표면

- 미인증: <상태 코드 + 코드 — 예: 401 `UNAUTHORIZED`>
- 인가 실패: <**존재 누설 금지**를 쓰면 404다. 프론트가 403만 다루면 어긋난다>
- 인증 만료 후 복귀: <재발급을 하는가, 어느 상태 코드에서 하는가>
