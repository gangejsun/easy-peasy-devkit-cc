## 3. 구규격 vs 신규격 (동일 스택 React+Vite, 판정 에이전트 1)

**판정: 기여(개선).** 핵심 증거:

1. 구규격 산출물의 숨은 결함 발견 — **양 허브의 Navigation Guide가 존재하지 않는 리소스
   5~6개를 참조**(깨진 링크). 신규격은 참조 전부 실재. 어제 "허브 대등~우세" 판정도
   이 결함을 놓친 것 (dangling 검사는 있었으나 어제 실험은 허브만 채점).
2. 허브 품질 비퇴보 — 지식 분산 없이 버전 정합성(RRv7·Tailwind v4·Zod v4)·에러표 정밀도 개선.
3. 리소스 실질성 — 허브 중복 ~10~15%, 나머지는 실질 심화. 병합 선언·공백 위임 문구가
   산출물에 남아 슬롯 표가 생성을 실제 통제했음을 보여줌.
4. 생성 간 드리프트 4건(1,000행 제한·리다이렉트 허용 목록·OTP·document.title 유실) —
   슬롯 구조와 무관한 지식 소환 편차. 규격서 개정 후보: **"스택 함정 목록" 내용 계약** 추가.

## 4. 함의

1. **"실전 검증 누적"은 양날이다.** 사용이 좋은 규칙을 승격시키는 동안, 감사 없는 축적은
   버전 드리프트(Zod v3·Tailwind v3·폐기 API)·도메인 잔재·중복 섹션·보안 결함을 함께 쌓았다.
   원본 우위의 근거였던 "축적"의 실체를 적대적으로 감사하자 우위가 뒤집혔다.
2. 어제 결론 중 유지되는 것: 규격서 방식의 파이프라인 적합성, 양방향 개선 루프.
   폐기되는 것: "원본을 계속 쓰는 현행 결정의 근거가 리소스 깊이와 검증 누적"이라는 전제 —
   깊이의 상당 부분이 부패 상태였다.
3. n=1×4쌍, 동일 날짜 생성이라는 한계는 유효. 단 핵심 결함은 판정 모델 의견이 아니라
   메인 세션이 파일:줄로 재확인한 실재다.
