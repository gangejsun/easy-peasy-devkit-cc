# 재기반 사후 감사 (A/B v3) — 최종본 3축 비교

- 날짜: 2026-08-21 · 선행: [guide-generation-ab-v2-2026-08-21.md](guide-generation-ab-v2-2026-08-21.md)
- 대상: 경로 B 재기반 결과물(커밋 0be7163)의 `nextjs-frontend-guide` · `nextjs-backend-guide`
- 방법: 감사 에이전트 3종(유실 감사 ×2, 병합 품질·규격 적합성 ×1) + **메인 세션 독립 재확인**

## 축 1 — 재기반본 vs 재기반 이전 원본 (자산 유실 감사)

**판정: 양 스킬 모두 순이득.** frontend 3,256→2,021줄(-38%), backend 3,153→1,833줄(-42%)로
압축하면서 지정 역이식 범주는 전부 이행됐고, 이전 원본의 오류가 다수 교정됐다.

단, 대체물 없이 사라진 자산과 이식 절단면이 확인되어 **전량 수리**했다(§4).

## 축 2 — 재기반본 vs 순수 생성본 (병합이 희석했는가)

**판정: 순 증분 (2,943→3,854줄, +31%).** 생성본 결함 수리 3건이 전부 이행됐고
(DELETE 0행→404는 PATCH·체크리스트·완전예제까지 범위 초과 전파), `components/shared` →
`layout`+`common` 리네임이 잔재 0으로 완결됐다.

예산이 내용을 잘라낸 사례 1건 확인: `api-routes.md`가 정확히 300줄에 도달하면서
GET 컬렉션 핸들러 정규형이 이탈(포인터로 봉합). → 규격서 체크리스트에 **290줄 경고**를 신설.

## 축 3 — 재기반본 vs 규격서 (적합성)

**판정: 양 스킬 필수 섹션 8개·필수 슬롯 7/7·dangling 0 전항 통과.** 메인 세션 독립 측정:

| 항목 | frontend | backend | 규격 |
| --- | --- | --- | --- |
| description | 437자 | 404자 | ≤450 ✓ |
| Quick Start 체크리스트 | 2개 × 8항목 | 2개 × 8항목 | 2개, 6~9항목 ✓ |
| Core Principles | 6규칙, 전부 good/bad 쌍 | 6규칙, 전부 good/bad 쌍 | 5~8, 쌍 필수 ✓ |
| 필수 보편 규칙 | 반복 UI 추출(원칙 3) ✓ | 입력 검증(1)·인증(2)·RLS(4) ✓ | 필수 ✓ |
| Navigation 커버리지 | 9/9 | 7/7 | 전 리소스 ✓ |

**단, 위반은 가이드가 아니라 규격서 쪽에 있었다** — 규격서 자기모순 3건을 수리(§3).

## 2. 유실 자산 복구

- **backend**: Edge Runtime 제약·rate limiting 해법 포인터·보안 헤더·구조화 로깅을
  신설 리소스 `edge-and-operations.md`로 복구(선택 슬롯 사용), 최상위 에러 봉투 보증,
  정렬 화이트리스트, 비폼 액션 시그니처 지침
- **frontend**: `useTransition` 패턴, 서버 측 검색·페이지네이션, 필드 단위 폼 에러,
  낙관적 UI 예제, 인증 조건부 헤더, export 규칙 명문화, 파일 내부 작성 순서

## 3. 규격서 자기모순 수리 (원본 진화가 드러낸 문언 오류)

1. **`[Preset:]` 접두사 금지** → 배포 형태별 조건화. 플러그인 배포 가이드는 게이팅이
   기능상 필수이므로 접두사를 쓴다. 프로젝트 생성물은 쓰지 않는다
2. **생성 스탬프 필수** → 생성된 가이드에 한정. 손으로 진화하는 도출 원본은 스탬프 없음이
   정상이며 위반이 아니다
3. **리소스 개수 "BaaS 4~6"** → 슬롯 수에서 도출(필수 7 + 선택 0~3 = 6~10)로 교체.
   기존 문구는 "선택 슬롯 0~3개"와 동시 충족 불가능한 내적 모순이었고, 백엔드 복잡도 축을
   frontend 파일 수에 적용한 범주 오류였다 (실측: 동일 스택에서 backend 6·frontend 9)

## 4. 규격서 역방향 갱신 (재기반본 → 규격서)

재기반본이 획득했으나 규격서에 대응 슬롯이 없어 **생성 가이드가 영영 받지 못할** 보편 범주를 이식:

- **존재 누설 금지** → Core Principles 계약 (부재와 권한 없음이 동일 응답)
- **권한 이중 방어 + 변이 행 수 확인** → 인증 경계·데이터 액세스 슬롯
- **환경변수 검증 단일 진입점** (부팅 시 실패, 공개/비밀 스키마 분리) → 입력 검증 슬롯
- **인증 플로우와 복귀 경로 안전성** (open-redirect, 실패 메시지 일반화, API/페이지 응답 분기)
  → 인증 경계 슬롯
- **생성 전 탐색 의무** (만들기 전 검색) → 컴포넌트 패턴 슬롯
- **경계 강제 수단** (server-only 마커) → 데이터 페칭 슬롯
- **오용 목록 형식** (버전 관용구 대조표·혼동 쌍) → resources 분할 규칙
- **T1 카드 참조에 실제 경로 명시 의무** → 데이터 액세스 슬롯
- **290줄 경고** → 자기 검증 체크리스트 3번

## 5. 수리 완료 검증 (메인 세션 독립 실행)

- P0 9건 전부 수리 확인: `/api` 401 분기 실재, `safeInternalPath()`가 제어문자 제거 후
  `new URL()` origin 대조, T1 카드 경로 3곳 명시(+ `app/api/**`에서는 자동 로드 안 되니
  경로로 열라는 안내), `textSearch` 두 형태 분리, Write 패턴 소유자 필터 + `.select()` 행 확인
- frontend: 정의-호출 짝 성립(`useQueryParams` 정의 신설), `getTasks` 무인자 통일,
  임계값 "2회 검토·3회 필수" 통일, `'use client'` 블록 전수 래퍼 보유
- 구조: dangling 0 · Navigation 9/9·7/7 · description 421자/444자(≤450) · doctor 19/19
- **예산 경고(신설 규칙 적용)**: 290줄 초과 리소스 **7개**
  (backend api-routes·database-patterns·validation-and-errors 각 300, complete-example 297,
  auth-boundaries 292 / frontend data-fetching 297, state-management 299).
  다음 이식은 반드시 기존 내용 삭제를 강제한다 — 추가 시 신규 리소스 분리를 우선한다

## 6. 미해결 — 사용자 판단 필요

**언어 비대칭**: 재기반 이전에는 두 가이드 모두 한국어 설명 + 영어 코드였으나(frontend 46줄,
backend 56줄에 한글), 재기반 후 frontend는 한국어 유지·강화(89줄), **backend는 1,833줄 전체가
영어**가 됐다. 저장소 관례(규칙·문서·커밋 전부 한국어)에서 벗어난 쪽은 backend다.
번역은 기계적이지만 방금 검증한 보안 서술을 다시 쓰는 위험이 있어 별도 판단 사항으로 남긴다.
