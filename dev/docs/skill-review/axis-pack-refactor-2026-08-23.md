## 이번 작업이 드러낸 것

### 1. 네 가이드가 서로 다른 시스템을 설명하고 있었다

프론트는 `task`(217회), 백엔드는 `note`(166회). 한글도 `작업` ↔ `노트`로 갈렸다.
두 쌍 모두 그랬으므로 우연이 아니라 **계약 양식의 구멍**이다 — 봉투·코드·페이지네이션은
못박았지만 도메인 어휘를 지정하지 않았다. 계약 템플릿에 `§0 도메인 어휘`를 넣고
게이트가 대조하게 했다. 개명 169곳 + 조사 교정.

### 2. 팩에는 두 형태가 있다

| 형태 | 예 | export |
| --- | --- | --- |
| 심볼 표면형 | `aws-container` (5리소스 1,191줄) | 25개 |
| 패턴 지식형 | `supabase` (2리소스 380줄) | **0개** |

BaaS 축이 얇은 것은 결함이 아니다 — 그 조합의 "백엔드 가이드"는 대부분 호스트 런타임
관심사이고 그것은 프론트엔드 축이 정한다. 게이트가 `symbolSurface: false`를 읽어
원장 역방향 검사를 건너뛰게 했다.

### 3. `nextjs-backend-guide`는 Supabase 팩이 아니었다

"Next.js가 호스팅하는 Supabase 백엔드"라 검증·에러·엣지 파일이 **문단 단위로** 얽혀
절 경계로 갈리지 않았다. 계획의 재조정 조건에 걸려 **깨끗이 갈라지는 것만 팩으로 보내고
나머지는 이음매가 흡수**하게 했다 (이음매 7파일). 그 결과 supabase 팩이 얇아졌고,
그것이 위 §2의 발견으로 이어졌다.

### 4. 계약은 기계가 읽는 문서다

`--pair`가 처음에 14건을 오인했다. 원인은 전부 **설명 산문 속 백틱**이었다:
"실측에서 백엔드가 `/notes`를 썼다"가 계약 요구사항으로 둔갑했다. 값은 목록·표 행에만
쓰고 산문·인용문은 설명으로 취급하도록 바꿨다.

### 5. 경계가 항상 HTTP인 것은 아니다

`nextjs × supabase`는 프론트가 자기 REST를 부르지 않는다 — 서버 컴포넌트가 데이터
계층을 직접 읽고 변이는 Server Action으로 간다. HTTP 계약을 양쪽에 요구하면 **정상
조합이 영구 FAIL**이 된다. 계약 절마다 `> surface: frontend|backend`를 선언할 수 있게
했다. 이 과정에서 `totalPages`가 와이어 필드가 아니라 프론트 파생값이라는 것도 드러났다.

### 6. 게이트가 자기 결함 4건을 드러냈다

| 결함 | 증상 |
| --- | --- |
| 예외 파일 열 미적용 | 공백 하나 때문에 모든 예외가 무시됨 |
| 이스케이프 파이프 절단 | `await (params\|...)` 정규식이 `await (params\`로 잘림 |
| `PGRST116` → `116` | 상태 코드 추출이 식별자 안의 숫자를 잡음 |
| 배송 스탬프가 예산 초과 유발 | 정확히 300줄인 원본이 팩으로 옮겨지는 것만으로 301줄 |

전부 `--self-test` 픽스처로 고정했다.

# 후속: vue 축 팩 생성 실측 (2026-08-23)

축 팩을 **파이프라인으로 생성**해 본 첫 사례. 자산과 실측을 함께 얻는 것이 목적이었다.

## 비용

| | 생성 | 감사 |
| --- | --- | --- |
| 벽시계 | **64분 3초** | **20분** |
| 서브에이전트 토큰 | 219,080 | 172,412 |
| 도구 호출 | 52 | 42 |
| 산출 | 10파일 1,946줄 | 결함 30여 건 |

**추정(20~40분)이 틀렸다.** 기존 실측(조합 전체 4,600줄 / 54분 / 62.3만 토큰)과 대조하면
**토큰은 −65%인데 벽시계는 오히려 늘었다.** 분량이 아니라 **검증 왕복 횟수가 벽시계를
지배**한다 — 이번 생성자는 정책 8건마다 결함 픽스처를 만들어 실제로 잡히는지 돌렸다.
"파일 단위 병렬로 임계 경로를 줄인다"는 계획의 가정은 이 부분을 놓치고 있었다.

## 감사가 잡은 것 — 기계 게이트가 전부 통과한 뒤에

생성자는 전항 통과를 자기보고했고 게이트도 통과했다. 그 뒤 독립 감사가 실행으로 확인한
결함이 나왔다. 원칙 5가 다시 성립했다.

### 최대 발견 — 오픈 리다이렉트가 출하본 전체에 있었다

`safeReturnTo`의 origin 검사가 점 세그먼트에 뚫린다:

```
safeReturnTo('/..//evil.example')  ->  '//evil.example'   브라우저: https://evil.example/
```

`new URL()`이 origin을 통과시킨 **뒤에** 점 세그먼트를 정규화해 `/..`가 선행 `/`를 삼킨다.
직접 형태(`//host`·`/\host`·`javascript:`)는 정상 차단되므로 원 감사들이 놓쳤다.

**신규 vue 팩만의 문제가 아니었다.** 같은 구현이 네 곳 전부에 있었고 4/4 공격 벡터가
모두 통과했다:

| 위치 | 출처 |
| --- | --- |
| `frontend/vue/routing.md` | 이번 생성물 |
| `frontend/react-vite/routing.md` | **v3.11.0 출하본** |
| `seams/nextjs+supabase` `safeInternalPath` | **v3.11.0 출하본** |
| `seams/react-vite+aws-container` `safeReturnPath` | **v3.11.0 출하본** |

수리: origin이 아니라 **출력 pathname**을 검증한다. 네 곳 모두 적용하고 실물에서 재시험해
6개 벡터 전부 차단, 정상 경로는 통과 확인.

> 이것이 "같은 스택 전제 안의 결함은 설치된 프로젝트에 도달해야 한다"는 규칙이 실재하는
> 이유다. 버전 문제가 아니라 결함이고, `pkgs` 메이저가 그대로이므로 갱신이 흘러간다.

### 실행으로 거짓 판정된 버전 주장 5건

| 주장 | 판정 |
| --- | --- |
| `declare module '*.vue'`가 vue-tsc에서 props를 `any`로 덮는다 | **거짓** — Volar 2 이후 SFC 실제 타입이 이긴다. 규칙은 유지하되 근거를 정정 |
| boolean prop은 기본값이 없으면 `undefined`가 된다 | **거짓** — Vue의 Boolean 캐스팅이 `false`로 만든다 |
| `<script setup>`은 아무것도 export할 수 없다 | **부분 거짓** — 값은 불가, `export type`은 가능 |
| pinia를 router보다 먼저 등록해야 가드에서 스토어를 쓴다 | **거짓** — 초기 내비게이션이 비동기라 순서 무관 |
| `:key="attempt"`를 올려야 깨진 상태가 안 되살아난다 | **거짓** — `v-if`/`v-else` 전환이 이미 재마운트를 강제. 죽은 코드였다 |

### 그 외 수리한 확정 결함

`:key="route.fullPath"`(필터 변경마다 입력이 날아감, 실행 확인) · msw 테스트의 import 누락
(`ReferenceError`) · `mountWithProviders`의 스프레드가 기본 plugins를 덮어씀 ·
`vite`의 `defineConfig`에 `test` 키가 없어 CI가 빨개짐 · `STORAGE_KEY` 리터럴 중복 ·
원장 계약 4건(`Task.status` 누락, `useTasksQuery` 인자 필수로 잘못 명시, `ApiError` 코드표
의무 누락, `http`의 에러 정규화 의무 누락) · 유령 심볼 5개 · 자기 규칙을 어긴 조립 예시 2곳 ·
백엔드 전제가 산문으로 샌 곳 1건.

### 정책도 감사 대상이었다

감사가 "잡기 쉬운 것만 잡아 통과율을 올린다"고 지적한 3건이 사실이었다 — `require` 정책이
**팩 자신의 텍스트로 충족**되어 이음매를 전혀 측정하지 못했다. 대상을 `seam`으로 옮겼다.
`no-dynamic-class-string`은 5개 형태 중 1개만 잡던 것을 넓혔고, 이 축 최대 위험인
**`@tanstack/react-query` import 금지**는 산문 경고만 있고 기계 방어가 없어 신설했다.
정책 11 → 15건이 됐고, 신규 2건은 결함 픽스처로 차단을 증명했다.

`no-options-api`를 `export default {`로 넓히려다 `tailwind.config.js`가 걸려 되돌렸다 —
설정 파일과 컴포넌트를 줄 단위로 구분할 수 없어 사람 검사로 내렸다.

## 아직 남은 것 (감사 지적 중 미수리)

전부 심각도 보통·낮음이며 조립·실행을 깨지 않는다:
색상 토큰 혼재(`slate-*` 18회 vs `surface-*` 8회) · 최소 터치 크기와 Button `sm` 충돌 ·
옵션 스토어 변형에 `reset()` 부재 · 인증 코드 위치가 두 곳으로 서술 · 캐치올 경로 형태 주석 ·
청크 프리페치 방법 미제시 · `mountWithProviders` 명명(Vue에서는 plugins) ·
`no-secret-env-prefix`가 이름 모양만 봄.

## 이 실측이 계획서에 주는 함의

계획서의 추정표(팩 1개 12~20분)를 **생성 64분 + 감사 20분 + 수리**로 교체한다.
그리고 더 중요한 것: **감사와 수리를 빼면 설치 가능한 물건이 나오지 않는다.** 이번에도
게이트 전항 통과 뒤에 오픈 리다이렉트가 남아 있었다. 사전 제작이 런타임 생성보다 나은
이유가 속도가 아니라 이것이다 — 유지자가 한 번 겪은 이 루프를 사용자마다 반복시키지 않는다.
