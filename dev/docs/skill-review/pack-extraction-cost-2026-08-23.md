## 이 진단이 분류를 수정한 부분

누출이 **계획이 이음매로 분류한 슬롯의 인접부에 정확히 몰렸다.** 분류가 맞았다는
증거이면서, 이음매 슬롯 정의를 두 군데 넓혀야 한다는 뜻이기도 하다:

1. **에러 봉투의 *방출 형태*는 이음매다.** 봉투 모양은 와이어 계약이고, 그것을 내보내는
   수단(`NextResponse.json` · `res.json` · `Response`)은 **서버 코드가 어디 사는가**의
   함수다 — 즉 프론트엔드 축에 의존한다. Zod 관용구·DB 제약 이중화·env 검증·에러 코드표·
   로깅 규칙은 축에 남는다.
2. **핸들러 계층 테스트는 이음매다.** 스키마 테스트(Layer 1)와 데이터 계층 통합 테스트
   (Layer 4)는 축이지만, 핸들러를 직접 호출하는 테스트는 핸들러 형태에 종속된다.

파일 수를 6~10 예산 안에 두기 위해 이 둘은 새 파일로 만들지 않고 이음매의
`api-endpoints.md`에 병합한다.
