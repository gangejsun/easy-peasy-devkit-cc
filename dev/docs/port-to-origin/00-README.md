# 원본 저장소 `.claude/` 하네스 v3 이식 — 사용법

이 디렉토리의 `phase-*.md` 9개는 **원본 저장소에 그대로 붙여넣는 프롬프트**다.
대상은 `~/Documents/easy-peasy-claudecode-devkit`의 `.claude/` — 그 저장소 자신의
작업 하네스다. `plugin/` 디렉토리는 건드리지 않는다.

## 이식의 출처

`easy-peasy-devkit-cc`(github.com/gangejsun/easy-peasy-devkit-cc)에서 2026-08-18 ~ 08-25
사이 수행한 하네스 전면 재설계. 커밋 78건, 345 파일, +39,933 / −11,405.
v2.0.0(2026-04-14, 원본과 마지막으로 같았던 시점) → v3.18.0.

원본 `.claude/`는 2026-05-20에서 멈춰 있고 v2 설계 그대로다:
규칙 14개 1,707줄 · 훅 11개 1,518줄 · 검증 스크립트 없음 · 워크플로우 그래프 없음.

## 붙여넣는 순서

| # | 파일 | 무엇이 생기는가 | 대략 |
| --- | --- | --- | --- |
| 0 | `phase-0-baseline.md` | 기준선 실측 + `platform-contract.md` | 1 세션 |
| 1 | `phase-1-verification-base.md` | `lib/common.sh` + `doctor.sh`(fast·self-test) | 1~2 세션 |
| 2 | `phase-2-hooks.md` | 훅 11 → 5 | 1~2 세션 |
| 3 | `phase-3-rules.md` | 규칙 14 → 9 (T0 + 상시 2 + T1 7) | 2 세션 |
| 4 | `phase-4-agents.md` | 에이전트 2종 재작성 | 1 세션 |
| 5 | `phase-5-graph.md` | `workflow.graph.json` + `--graph`·`--usage`·`--lessons` | 1~2 세션 |
| 6 | `phase-6-skills.md` | 스킬 33개 정제 | 1~2 세션 |
| 7 | `phase-7-guides.md` | 축 팩·이음매 체계 (팩 본문 제외) | 2 세션 |
| 8 | `phase-8-evaluation.md` | 7축 평가 스킬 + 최종 전수 검증 | 1 세션 |

**한 번에 하나씩.** 각 단계는 끝에 검증 명령과 완료 기준(DoD)을 갖는다. DoD를
통과하지 못한 채 다음 단계로 가지 않는다 — 3단계의 규칙이 도달하는지는 1단계의
doctor가 판정하고, 5단계의 계측은 2단계의 훅이 방출한다.

**순서를 바꾸지 않는다.** 특히 1단계(검증 기층)가 먼저다. devkit-cc는 훅을 먼저 쓰고
doctor를 나중에 만들어서 "훅 8개가 4개월간 죽은 채 아무 신호도 내지 않은" 상태를
발견하지 못했다. 원본에는 그 순서를 뒤집어 넘긴다.

## 번역 표 — 모든 단계에서 유효하다

devkit-cc는 **플러그인**이고 원본 `.claude/`는 **프로젝트 로컬 하네스**다.
전제가 다르므로 복사가 아니라 번역이다.

| devkit-cc (플러그인) | 원본 `.claude/` |
| --- | --- |
| `${CLAUDE_PLUGIN_ROOT}` | **치환되지 않는다** (플러그인 스킬 전용). 훅·스크립트는 `${CLAUDE_PROJECT_DIR}` 또는 `.claude/` 상대 경로를 쓴다 |
| `hooks/hooks.json` 자동 발견 | `.claude/settings.json`의 `hooks` 키 |
| `scripts/` (플러그인 루트) | `.claude/scripts/` |
| `rules/` → `install-rules.sh`가 프로젝트로 설치 | `.claude/rules/`가 곧 정본. **설치기 불필요** |
| T0 운영계약을 SessionStart 훅이 출력 (플러그인은 규칙을 배포할 수 없어서) | `paths:` 없는 **규칙 파일 하나가 정본**이다. 훅의 T0 출력 절은 뺀다 — 둘 다 하면 같은 내용이 두 번 상주한다 |
| `doctor --consumer` (소비자 부재를 합성) | 이 저장소가 곧 소비자 → **실제 편집 경로로 실측**한다 |
| 버전 4곳 동시 인상 · 마켓플레이스 | 없음. 버전은 규칙 카드의 `epcc-rule-version`만 |
| `${CLAUDE_SKILL_DIR}` | 그대로 유효 (프로젝트 스킬에서도 치환된다) |

## 이식 대상 원칙 13조

파일만 복제되고 판단 기준이 안 옮겨가면 6개월 뒤 같은 자리로 돌아온다.
아래는 v3를 만든 판단 기준이고, **각 단계의 지시보다 이쪽이 상위**다.

1. **규모가 아니라 되돌림 가능성으로 판정한다.** S/M/L은 사람 판단을 요구해 드리프트하고
   틀린 변수를 본다 — 5줄 마이그레이션이 400줄 리팩토링보다 위험하다.
2. **도달 경로를 검증한다.** v2에서 규칙 697줄이 4개월간 어느 프로젝트에도 도달하지
   못했다(플러그인 매니페스트에 `rules` 컴포넌트 타입이 없다). 규칙을 만들었으면
   그것이 **의도한 시점에 실제로 로드되는지** 즉시 확인한다.
3. **Script가 할 수 있는 것은 Script에, LLM만 할 수 있는 것은 LLM에.**
   검출된 결함의 다수가 안목이 아니라 grep으로 잡혔다.
4. **차단 장치는 3상태다.** 위반 확인 → 차단 · 위반 없음 확인 → 통과 ·
   **판정 불가(도구 부재·입력 없음·오프라인) → 차단하지 않고 명시 보고 후 통과.**
5. **오탐은 사용자가 훅을 끄게 만들고, 꺼진 훅의 차단력은 0이다.**
6. **살아있음 ≠ 작동함.** 차단 장치를 만들었으면 결함을 심어 차단을 증명하고,
   **심기 자체가 유효했는지 먼저 확인한다** — devkit-cc에서 없는 파일명을 노려
   심기가 실패했는데 "통과"로 보인 적이 있다(차단 증명이 no-op이었다).
7. **계측기 자신을 의심한다.** v3 평가에서 신규 결함 5건 중 4건이 doctor 자신과
   배포 경로에서 나왔다. "무엇을 재는가"를 개선하는 동안 "재는 도구가 맞는가"를
   아무도 보지 않았다.
8. **생성자 ≠ 검증자.** 생성 에이전트는 매번 전항 통과를 자기보고했으나 독립 감사가
   결함을 찾았다. 그리고 **감사 보고도 재확인 대상이다** — 감사자의 지적 일부가 오판이었다.
9. **승격의 증거는 선언이 아니라 ① 대응 자산의 diff ② 파일에서 사라진 항목이다.**
   v2는 "✅ 승격됨"을 22건 선언하고 규칙은 0건 바뀌었다. 루프가 돌면 `lessons.md`는 **줄어든다.**
10. **플랫폼 동작은 출처 URL과 확인 날짜로 주장한다.** 기억으로 단정해서 생긴 결함이
    세 부류였다 — 치환되지 않는 자작 변수 28곳, `.claude/rules/`가 네이티브인 줄 몰라
    라우팅을 갱신 경로 없는 곳에 배치, 사실이 아닌 전제.
11. **사본은 드리프트 원천이다.** 단일 정본 + 인용. 같은 규범을 두 파일이 주장하게 두지 않는다.
12. **분량은 품질이 아니고, 예산 상한에 붙이지 않는다.** 300줄 예산에 도달한 파일은
    다음 변경 때 저자가 아니라 예산이 삭제 대상을 고른다.
13. **개입 근거 2줄.** (a) 막으려는 실패 — 2회 이상 관측된 것 (b) 잘 되던 것을 망칠 위험.
    (a)를 못 쓰면 그것은 가설이지 패턴이 아니다 — 추가하지 않는다.

## 이식하면서 고치는 것 (출처의 현존 결함 3건)

devkit-cc의 `dev/docs/harness-evaluation/v3.md`가 잡은 결함 중 셋은 원본에도 그대로
재현되므로 **결함째 옮기지 않는다.** 해당 단계 프롬프트에 수정된 형태로 들어 있다.

| ID | 무엇 | 어디서 고치는가 |
| --- | --- | --- |
| E-09 | self-test의 픽스처 주입이 **저장소 자신의 계측 로그를 오염**시킨다. 그 위에서 판정한 사용량 통계가 전부 자기 픽스처 흔적이었다 | phase-1 — 기록 위치를 `epcc_state_dir()`로 빼고 `EPCC_STATE_DIR`로 격리 |
| E-10 | `[ … ] && warn … \|\| ok …` — `warn`은 `$2`가 비면 반환값이 1이라 **실패가 있을 때 warn과 ok가 둘 다 실행**된다. 통과 카운터에 유령이 섞이고 실제 신호가 덮인다 | phase-5 — `if/else` |
| E-11 | `살아있는 훅 N/M`의 분모가 hooks 엔트리 수라 한 스크립트가 2이벤트에 걸리면 **분자가 구조적으로 분모에 도달 못 한다** → 영구 미달 경고 | phase-5 — 분모를 고유 스크립트 수로 |
