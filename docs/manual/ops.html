자기 수리

하네스는 스스로를 재고 고칩니다

세 번째 루프 — 빌트인 재평가 (P6-②)

빌트인은 모델과 함께 계속 좋아집니다. 그래서 "이 커스텀 자산이 아직 필요한가"는 한 번 묻고 끝나지 않습니다.

판정의미
네이티브로 대체빌트인이 이제 충분합니다 — 커스텀을 폐기합니다
커스텀 유지빌트인이 다루지 않는 영역입니다 — 근거를 적습니다
합성커스텀은 빌트인을 감싸는 얇은 층이어야 하고, 빌트인이 이미 하는 일을 재구현해서는 안 됩니다
생략 조건이 둘 다여야 합니다 — 직전 판정이 30일 이내 이고 그 뒤 하네스 자산 커밋이 0건일 때만 생략합니다. 날짜만으로는 생략하지 않습니다.

불변식

이건 절대 깨지 않습니다

  • 판정 불가 ≠ 차단오탐 → 사용자가 훅을 끔 → 차단력 0
  • 사본을 만들지 않는다 (단일 정본 + 참조)드리프트. v2를 죽인 실패 모드
  • 도달 경로를 검증한다규칙 697줄이 4개월간 아무에게도 안 닿음
  • 차단 장치는 차단을 증명한다 — 사유까지죽은 장치가 살아있는 척함
  • 문서의 수는 기계가 대조한다거짓 문장이 배포됨
  • 소비자 것은 명시 요청 없이 안 건드린다신뢰 상실
  • 기존 코드 패턴이 플러그인 가이드를 이긴다하네스가 프로젝트를 조용히 덮어씀
  • 안전 바닥은 프로젝트가 올릴 수만 있다안전장치가 우회 가능해짐

⑦과 ⑧은 한 쌍입니다 — 층이 둘이고 방향이 반대

층내용규칙
안전 바닥되돌림 분류 · 검증 의무 · 시크릿 경계 · 분기점프로젝트는 올릴 수만 있습니다. 내리려면 사용자의 명시 요청
올리는 통로: .claude/resources/에 파일을 두면 스킬이 자동 참조합니다
절차 · 양식가이드 팩의 스택 관행 · 스킬 워크플로 · 네이밍 · 문서 형식프로젝트가 이깁니다. 우선순위: 사용자 요청 → 프로젝트 CLAUDE.md → 프로젝트 .claude/rules/ → 저장소의 기존 코드 패턴 → 플러그인 가이드
기존 코드 패턴이 플러그인 가이드를 이긴다가 핵심입니다. 가이드가 권하는 형태와 저장소가 실제로 쓰는 형태가 다르면 저장소를 따릅니다. 가이드를 근거로 기존 패턴을 바꾸는 것은 리팩토링이고, 리팩토링은 별도 요청이 있을 때 합니다.

확인 항목방법왜
설치 성공 ≠ 자산 도달claude plugin details의 Skills 개수설치가 됐다는 말이 자산이 보인다는 뜻은 아닙니다
카드 도달소비자의 .claude/rules/를 눈으로v2가 4개월간 놓친 것이 정확히 이 한 가지입니다
훅 실제 발화소비자 쪽에서 doctor --usage등록됐다는 것과 발화한다는 것은 다릅니다
첫 세션의 오탐신규 설치 직후 세션을 한 번 열어본다「훅 생존 현황」이 신규 설치에서 기회가 없던 것을 미발화로 세던 오탐이 있었습니다
이 저장소에 만들지 않는 것 — epcc.config.json · dev/active/ · 스택 가이드. 여기는 플러그인 소스이고 소비자 프로젝트가 아닙니다. rules/는 배포될 자산이지 여기서 자동 로드되는 설정이 아닙니다 — 그래서 CLAUDE.md가 따로 필요합니다.
