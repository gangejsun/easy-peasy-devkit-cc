배포

버전은 4곳이 아니라 5단계

진단

doctor가 대신 봐줍니다

--fast

구조 검사 — 훅 규격 · 룰 예산 · dangling · 매니페스트 · 손으로 적은 수

--graph

도달 불가 노드 · dangling 엣지 · 읽는 노드 없는 저장소

--self-test

훅에 실제 stdin 픽스처를 넣어 효과 대조 — 차단 장치를 건드렸으면 필수

--consumer

소비자 레이아웃 실증 — 훅·설치기를 건드렸으면

--lessons

교훈 집계 + 승격 후보 + 장치별 오탐 수축 후보

--inventory

자산 인벤토리 — 판정 없음. 하네스 평가의 입력

문서에 손으로 적은 수는 반드시 낡습니다. 그래프 노드·엣지, 스킬 개수, T1 줄 수, 에이전트 도구 목록을 doctor가 실물과 대조합니다. 그래프를 늘렸으면 README와 해부 문서의 수도 같이 고치세요 — 안 고치면 실패합니다. 이건 기능입니다.

불변식

이건 절대 깨지 않습니다

  • 판정 불가 ≠ 차단오탐 → 사용자가 훅을 끔 → 차단력 0
  • 사본을 만들지 않는다 (단일 정본 + 참조)드리프트. v2를 죽인 실패 모드
  • 도달 경로를 검증한다규칙 697줄이 4개월간 아무에게도 안 닿음
  • 차단 장치는 차단을 증명한다 — 사유까지죽은 장치가 살아있는 척함
  • 문서의 수는 기계가 대조한다거짓 문장이 배포됨
  • 소비자 것은 명시 요청 없이 안 건드린다신뢰 상실
  • 기존 코드 패턴이 플러그인 가이드를 이긴다하네스가 프로젝트를 조용히 덮어씀
  • 안전 바닥은 프로젝트가 올릴 수만 있다안전장치가 우회 가능해짐

⑦과 ⑧은 한 쌍입니다. 층이 둘이고 방향이 반대입니다 — 안전 바닥(되돌림 분류·검증 의무·시크릿 경계)은 프로젝트가 올릴 수만 있고, 절차·양식(스택 관행·네이밍·문서 형식)은 프로젝트가 이깁니다.
