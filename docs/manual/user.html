판정 방식 — 오탐을 막는 장치

  • 세그먼트 단위로 봅니다. ; && || 로 이어진 명령은 각각 따로 판정합니다.
  • 면제는 첫 토큰으로. 문자열 포함으로 면제했다가 doctor.sh …; psql -c "DROP TABLE"이 통째로 통과한 사고가 있었습니다.
  • 조사 명령은 통과. 시크릿 문자열이 들어 있어도 파일을 쓰지 않으면 막지 않습니다.
  • 판정 불가는 차단이 아닙니다. 입력을 파싱 못 하면 알리고 통과시킵니다.

축은 자기가 못 박는 것을 반드시 선언해야 합니다. 선언하지 않으면 그 축의 지침이 틀린 프로젝트에도 적용됩니다.

실례 — nextjs 축은 페칭·라우팅·서버 런타임을 스스로 정하므로, 따로 못 박는 것은 클라이언트 상태와 폼뿐입니다: store: zustand · forms: react-hook-form. Redux나 Jotai를 확정한 프로젝트에는 이 팩의 상태 관리 절이 틀린 지침이 됩니다 — 그래서 선언이 의무이고, 누락되면 검증이 FAIL입니다.
