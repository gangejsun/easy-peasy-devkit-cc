# 운영 매뉴얼 — 하네스를 고치고 유지보수하는 사람을 위해

이 저장소는 **Claude Code 플러그인의 소스**입니다. 소비자 프로젝트가 아닙니다.
`rules/`는 소비자에게 배포될 자산이지 여기서 자동 로드되는 설정이 아닙니다.

## 이 문서의 경계 — 어디서 무엇을 찾나

**정본을 여기에 옮겨 적지 않습니다.** 사본은 드리프트 원천입니다. 이 문서는
**"이럴 때 무엇을 어떤 순서로 하는가"**만 담고, 판정 기준은 원본을 가리킵니다.

| 알고 싶은 것 | 어디로 |
| --- | --- |
| **이럴 때 어떻게 하나** (절차·런북) | **이 문서** |
| 이 장치가 **왜** 이렇게 생겼나 (설계 근거) | [harness-anatomy.md](harness-anatomy.md) — 1,132줄 |
| 하네스를 고칠 때의 **규범** (지켜야 할 것) | `rules/harness-change.md` — T1 카드 |
| Claude Code가 **보장하는 것** (플랫폼 계약) | [platform-contract.md](platform-contract.md) |
| 실제로 **지금 어긋난 것**이 있나 | `scripts/doctor.sh` — 기계 판정 |
| 사용자는 이걸 **어떻게 쓰나** | [user-manual.md](user-manual.md) |
| 과거에 **무엇을 틀렸나** | `docs/lessons.md` · [lessons-archive.md](lessons-archive.md) |

> **읽는 순서(신규 관리자)** — ① `rules/harness-change.md`(규범) → ② 이 문서 §1~§2(부품과
> 절차) → ③ `doctor.sh --help`(진단 도구) → ④ `docs/lessons.md`(과거의 실패) →
> ⑤ 필요할 때 `harness-anatomy.md`의 해당 절. **④를 건너뛰지 마세요** — 여기 기록된 실패는
> 대부분 "그럴듯했지만 효과가 없던 수정"입니다.

## 2. 런북 — 시나리오별 절차

### 2.1 자산을 추가하고 싶다

**먼저 3-질문을 통과해야 합니다.** 하나라도 YES면 중단입니다.

| # | 질문 | YES면 |
| --- | --- | --- |
| Q1 | 기존 훅/규칙/스킬/**Claude Code 빌트인**과 역할이 겹치나 | 기존 것을 확장하거나, 빌트인을 쓰거나, 빌트인 위에 부족분만 얇게 덧댐(**합성**) |
| Q2 | 모델 성능이 좋아져서 이제 불필요한 것 아닌가 | 중단 |
| Q3 | 잘 되던 것을 굳이 바꾸는 것 아닌가 | 중단 |

**Q1의 "빌트인"은 실제로 확인합니다.** `/code-review`·`/simplify`·`/security-review`·
`skill-creator`·`/init`·`/run`·`/loop`은 Claude Code가 제공합니다. 이들과 **경쟁하는 자산을
만들지 않습니다.** 판정은 셋뿐입니다 — **네이티브로 대체 · 커스텀 유지 · 합성.**

통과했다면 **해결 수단 우선순위**를 지킵니다:

```
1. 기존 문서 수정 (1~3줄 추가)   ← 가장 선호
2. 기존 훅 로직 확장
3. 기존 스크립트에 기능 추가
4. 신규 스크립트 작성            ← 가장 후순위
```

그다음 **도달 경로 검증**을 반드시 합니다:

- 조건부 로딩이면 `paths:`가 실제 편집 경로를 포함하나
- 플러그인 자산이면 Claude Code가 **지원하는 컴포넌트 타입**인가
  (`skills`/`commands`/`agents`/`hooks`/`mcpServers`/`outputStyles`/`lspServers` — **`rules`는 없습니다**)
- 프로젝트에 있어야 하는 파일이면 `epcc-init`에 설치 단계가 있나
- **모든 프리셋/스택 조합에서 도달하나** — 보편 규범을 한 프리셋 전용 스킬에 두지 않습니다

마지막으로 **그래프에 선언**합니다. 선언하지 않으면 doctor가 「미선언 스킬/훅」으로 잡습니다.

### 2.2 개입(훅·규칙·스킬·브리핑)을 추가·수정했다

**커밋 메시지나 PR에 2줄을 적습니다. 예외 없습니다.**

| 줄 | 내용 |
| --- | --- |
| (a) | **막으려는 실패** — 2회 이상 반복 관측된 것 |
| (b) | **잘 되던 것을 망칠 위험** |

**(a)를 못 쓰면 그것은 가설이지 패턴이 아닙니다 — 추가하지 않습니다.**
개별 사례의 정답을 하드코딩하지 않고, 다음 작업에도 재사용되는 개입만 남깁니다.

> 📌 (a)를 문자 그대로 충족하지 못하면서도 추가할 가치가 있다면, **그 사실을 커밋에
> 명시**하세요. "관측 카운트가 아니라 구조적 결손으로 판정했다"고 적는 것이 조용히
> 넘어가는 것보다 낫습니다 — 다음 사람이 재평가할 수 있습니다.

### 2.3 규칙 카드를 고친다

1. `paths:` 프론트매터가 여전히 맞나 확인 — 넓으면 매 세션 헛돌고, 좁으면 도달 못 합니다
2. `<!-- epcc-rule-version: X.Y.Z -->` 스탬프를 현재 버전으로
3. `workflow-routing.md`에는 **`paths:`를 넣지 않습니다** (doctor `--fast`가 실패시킵니다)
4. 줄 수 변화 → `README.md`의 「T0 N줄 + T1 M개 L줄」 주장이 낡습니다 — doctor가 대조합니다
5. 카드 본문에 **플러그인 저장소 맥락의 경로를 쓰지 않습니다** — 소비자에겐 없는 파일입니다.
   `<플러그인-루트>/…` 표기를 씁니다

### 2.4 스킬을 고친다

- **description은 상주 비용입니다** — 25개 합계 12,000바이트 예산. 늘리면 모든 세션이 냅니다
- 본문은 호출 시에만 로드되므로 상세는 본문에
- 스킬 전용 스크립트는 `skills/<스킬>/scripts/`에 두고 **`${CLAUDE_SKILL_DIR}`**로 호출합니다.
  자작 표기는 치환되지 않아 소비자에서 실패합니다 (doctor가 검출)
- 루트 `scripts/`는 **훅·doctor·설치기 전용**입니다. 검사 스크립트를 거기 두면 doctor의
  자기 lint가 정규식 문자열을 오탐합니다

### 2.5 훅을 고친다 — 침묵 실패 방지

**아래를 실제로 실행합니다. 생략 불가입니다.**

1. `scripts/lib/common.sh`를 source하고 `epcc_begin`으로 시작
   - 루트는 `epcc_root()`로만. `BASH_SOURCE`·`dirname ../..` **금지**
   - 숫자는 `epcc_num()`을 통과. `|| echo 0` **금지**
2. 출력은 `epcc_emit_context` / `epcc_emit_block`으로만
   - **이벤트마다 지원 필드가 다르고, 미지원 필드는 조용히 무시됩니다**
   - `Stop`은 `decision`/`reason` 미지원 → `continue` + `systemMessage`
   - `PreCompact`/`SessionEnd`는 평문 stdout이 컨텍스트에 안 들어감 → JSON 필요
3. `doctor.sh --default` + `--self-test` 통과 확인
4. `hooks.json`에 등록했으면 **`workflow.graph.json`에도 노드/엣지 추가**

### 2.6 검사 스크립트를 만든다 (훅이 아닌 것)

**훅과 규약이 다릅니다.**

| 항목 | 규약 |
| --- | --- |
| `common.sh` | **source하지 않습니다** — `set -Eeuo pipefail`과 ERR trap이 "모든 검사를 끝까지 돌린다"와 충돌 |
| 대신 | `doctor.sh`의 `ok/warn/bad/sec` + `num()` + `--help`=헤더 주석을 **복사**하고 `return 0` 명시 |
| 왜 `return 0` | 원본 `bad`/`warn`은 `$2`가 비면 반환값이 1이라 `A && warn || ok`가 **양쪽 다 실행**됩니다 |
| 종료 코드 | `0` 통과 · `1` 결함 · `2` **판정 불가** |
| 참고 구현 | `skills/ui-ux-design/scripts/ui-probe.sh` · `design-sync.sh` |

### 2.7 차단 장치를 만들었다 — 차단을 증명한다

**살아있음 ≠ 작동함입니다.**

1. 결함을 심은 픽스처가 **exit 1(또는 2)을 받는지**
2. 그리고 **의도한 이유로** 받는지 (사유 문구 대조를 자기검사에 내장)
3. **면제도 같은 강도로 증명합니다** — 우회 시도 픽스처가 여전히 차단되는지

> ⚠️ **면제는 첫 토큰으로 판정합니다.** 문자열 포함(`*x*`)으로 면제하면
> `…doctor.sh …; psql -c "DROP TABLE"`이 통째로 통과합니다(실제 사고). 명령이
> 연결자(`;` `&&` `||`)로 이어지면 **세그먼트마다 따로** 판정합니다.

> 📌 **픽스처에 실제 자격증명 형태를 파일로 두지 마세요.** GitHub push protection이 푸시를
> 막습니다. `@@FILL<n>@@` 플레이스홀더를 쓰고 `doctor.sh`의 `_fx_fill()`이 실행 시점에
> 조립하게 하세요 — 파일엔 안 남고 차단 증명의 강도는 그대로입니다.

### 2.8 차단 장치는 3상태입니다

| 상태 | 행동 |
| --- | --- |
| 위반 확인 | 차단 |
| 위반 없음 확인 | 통과 |
| **판정 불가** (도구 부재·입력 없음·오프라인) | **차단하지 않고**, 판정 불가임을 명시 보고하고 통과 |

**판정 불가를 차단으로 접으면 오탐이 되고, 오탐은 사용자가 훅을 꺼버리게 만들며, 꺼진
훅의 차단력은 0입니다.** 없음으로도 있음으로도 단정하지 않습니다.

### 2.9 자산을 개명·이동·삭제했다 — 사라진 이름 쪽을 본다

도달 경로 검증이 "새 이름이 닿나"를 본다면, 이것은 **"옛 이름을 가리키던 것들"**을 봅니다.
개명된 자산은 새 이름으로 잘 놓여 있어 **도달 검사를 언제나 통과합니다** — 잔재는 사라진
이름 쪽에 남습니다.

1. **사라지는 이름 목록을 먼저 확정** — 기억이 아니라
   `git diff --diff-filter=RD --name-only`가 출처
2. **저장소 전체를 훑습니다** — `.claude/`가 아니라 전체입니다.
   `README.md`·`docs/`·`guides/`·`dev/docs/`·`workflow.graph.json`이 빠지는 자리입니다
3. **0건을 명령으로 확인** — "전수 확인함"이라 적는 것은 증거가 아닙니다

> 실측: 완료 조건은 "저장소 전체 0건"이라 적혔지만 실행된 명령은 두 곳만 봤고, 빠진
> `dev/`에 정확히 옛 이름이 남았습니다. **명령이 곧 사실이고, 문장은 아닙니다.**

### 2.10 자산을 폐기한다

| 대상 | 방법 |
| --- | --- |
| **소비자 프로젝트**의 `.claude/` 커스텀 | `.claude/deprecated/`로 이동 + 파일명에 만료일(기본 14일). 문제없으면 삭제 확정, 생기면 복구. **폐기 결정은 항상 사용자 승인** |
| **이 저장소**의 자산 | git이 롤백을 보장하므로 shadow 없이 삭제 |

### 2.11 버전을 올린다 — **4곳이 아니라 5단계입니다**

```
① 4곳 동시 인상   plugin.json · package.json · README 배지 · marketplace.json(2군데)
② 커밋
③ claude plugin validate .
④ git push origin main
⑤ claude plugin tag --push
```

**①에서 끝나면 소비자는 아무것도 받지 못합니다.** 소비자는 태그로 버전을 받습니다.

| 주의 | 내용 |
| --- | --- |
| `marketing/`의 `epcc-marketing` | **독립 버전** — 이 4곳과 함께 올리지 않습니다 |
| `harness/`의 `epcc-harness` | **독립 버전** — 하네스 저작자만 설치하므로 소비자 릴리스와 무관합니다 |
| 버전 인상 시 가이드 검증 | `--self-test` 대신 **`--regress`** (출하 자산 회귀) |
| 푸시가 막히면 | GitHub push protection일 수 있습니다 — §2.7의 픽스처 주의 참조 |

### 2.12 결함이 나왔다 / 오탐이 나왔다

| 상황 | 경로 |
| --- | --- |
| 사용자가 코드·접근·워크플로우를 지적 | **즉시** `docs/lessons.md`에 기록 (형식은 `rules/lessons.md`) |
| 같은 카테고리 3건 이상 | **자산 승격** — 대응 장치를 만들고 `lessons-archive.md`로 물리 이동 |
| 오탐(false-positive) | `장치:` 줄을 반드시 적습니다 — `doctor --lessons`가 **장치별**로 셉니다 |
| 같은 장치에서 오탐 2건 이상 | **규칙을 추가하는 게 아니라 조건을 좁힙니다** |
| 하네스 전반 점검 | `/harness-evaluation` → `dev/docs/harness-evaluation/vN.md` — **`epcc-harness` 플러그인 전용**(하네스를 만드는 사람만 설치) |

> 🔁 **빌트인 재평가는 주기적입니다.** `/harness-evaluation`의 P6-②가 "이 커스텀 자산이
> 아직 필요한가"를 다시 던집니다. 직전 판정이 30일 이내 **이면서** 그 뒤 하네스 자산 커밋이
> 0건일 때만 생략합니다 — **날짜만으로는 생략하지 않습니다.**

## 3. 진단 도구 — `doctor.sh` 모드별 색인

| 모드 | 무엇을 답하나 | 언제 |
| --- | --- | --- |
| `--fast` | 구조 검사 (훅 규격·룰 예산·dangling·매니페스트·수치 주장) | 상시 |
| `--graph` | 그래프 검증 (도달 불가 노드·dangling 엣지·저장소 소비 경로) | 그래프를 건드렸을 때 |
| *(인자 없음)* | `--fast --graph` | 기본 |
| `--self-test` | 훅에 **실제 stdin 픽스처**를 주입해 효과 대조 | 훅·차단 장치를 건드렸을 때 |
| `--consumer` | 소비자 레이아웃 실증 (캐시 경로 + 빈 프로젝트에서 훅 실행) | 훅·설치기를 건드렸을 때 |
| `--usage` | 훅 하트비트 · 스킬 호출 · 엣지 traversal | 계측 확인 |
| `--lessons` | 교훈 카테고리 집계 + 승격 후보 + **장치별 오탐 수축 후보** | 주기적 |
| `--inventory` | 영역별 자산 인벤토리 (판정 없음) | `/harness-evaluation`의 입력 |
| `--all` | 위 전부 | 릴리스 전 |

### 변경 후 필수 조합

```bash
npm test                            # doctor --default · --self-test · 렌더 증명
bash scripts/doctor.sh --consumer   # 훅·설치기를 건드렸으면
bash skills/stack-guide-generator/scripts/guide-gate.sh --self-test   # 가이드 하네스
bash skills/stack-guide-generator/scripts/pack-smoke.sh --self-test
bash skills/ui-ux-design/scripts/design-sync.sh --self-test           # 토큰 대조
```

### doctor가 대신 봐주는 「손으로 적은 수」

문서에 손으로 적은 수는 **반드시 낡습니다.** doctor가 실물과 대조하는 항목:

- `README.md`의 「노드 N · 엣지 N」·「스킬 N」·「T1 N개 L줄」
- `docs/harness-anatomy.md`의 그래프 `kind` 표 · 「노드 N · 엣지 N」·「T0 주입 N줄」
- T0 예산 수치 (`doctor.sh`의 `T0_BUDGET` 상수가 정본)
- 에이전트 `tools:` 목록 ↔ README·해부 문서의 표

> 💡 그래프 노드/엣지를 늘렸다면 **README와 해부 문서의 수를 같이 고치세요.** 안 고치면
> doctor `--default`가 실패합니다. 이건 기능입니다.

## 4. 절대 깨지 않는 불변식 8개

| # | 불변식 | 깨지면 |
| --- | --- | --- |
| ① | **판정 불가 ≠ 차단** | 오탐 → 사용자가 훅을 끔 → 차단력 0 |
| ② | **사본을 만들지 않는다** (단일 정본 + 참조) | 드리프트. v2를 죽인 실패 모드 |
| ③ | **도달 경로를 검증한다** | 선언만 되고 아무에게도 안 닿음 (697줄 × 4개월) |
| ④ | **차단 장치는 차단을 증명한다** (사유까지) | 죽은 장치가 살아있는 척함 |
| ⑤ | **문서의 수는 기계가 대조한다** | 거짓 문장이 배포됨 |
| ⑥ | **소비자 것은 명시 요청 없이 안 건드린다** (`AGENTS.md`·`.github/`·`docs/`) | 신뢰 상실 |
| ⑦ | **기존 코드 패턴이 플러그인 가이드를 이긴다** | 하네스가 프로젝트를 조용히 덮어씀 |
| ⑧ | **안전 바닥은 프로젝트가 올릴 수만 있다** (되돌림 분류·검증 의무·시크릿 경계) | 안전장치가 우회 가능해짐 |

**⑦·⑧이 한 쌍입니다.** 층이 둘이고 방향이 반대입니다:

| 층 | 내용 | 규칙 |
| --- | --- | --- |
| **안전 바닥** | 되돌림 분류·검증 의무·시크릿 경계·분기점 | 프로젝트는 **올릴 수만** 있음 |
| **절차·양식** | 스택 관행·스킬 워크플로·네이밍·문서 형식 | **프로젝트가 이김** |

## 5. 반복되는 함정 — `lessons.md`에서 뽑은 것

| 함정 | 실제로 일어난 일 | 예방 |
| --- | --- | --- |
| **보편 규범을 프리셋 전용 자산에 둠** | 다른 스택 조합에서 도달 0 | 보편이면 **T1 카드**가 배포 수단 |
| **개명 후 옛 이름을 안 따라감** | 거짓 문장이 4.5개월 배포됨 | §2.9 역추적 |
| **중복을 지우며 감시 검사의 대상도 없앰** | 검사가 조용히 무의미해짐 | 지울 때 그것을 보던 검사도 확인 |
| **실행 경로 아닌 도구로 재고 그 위에 개편안을 쌓음** | 전제부터 틀린 계획 | 실측은 **실행 경로에서** |
| **서브에이전트의 실측을 재검증 없이 씀** | 낡은 근거로 결정 | 「참조 신선도」 4축 재검증 |
| **요청은 케이스 추가인데 계획이 하네스 개편으로 부풂** | 범위 폭발 | 요청된 것만 |
| **기회가 없던 것을 미발화로 셈** | 첫 세션이 "훅 고장"으로 시작 | 분모를 정확히 |

> 📌 **이전 진단·리뷰 보고서는 힌트로만 받습니다.** "Critical N건"이라 적혀 있으면 N건이
> 여전히 미해결인지 **현재 정본을 하나씩 재검증한 것만** 채택합니다.

## 6. 이 저장소에서 할 수 **없는** 것

**실사용 검증은 여기서 못 합니다.** 이 저장소에는 소비자가 없습니다. 따라서 **규칙이 소비자
프로젝트에 실제로 도달하는지는 여기서 확인할 수 없습니다.**

신규 프로젝트에 플러그인을 설치해 검증할 때 **`.claude/rules/`에 T1 카드가 실제로 설치됐는지
반드시 확인하세요** — v2가 4개월간 놓친 것이 정확히 이 한 가지입니다.

| 확인 항목 | 방법 |
| --- | --- |
| 설치 성공 ≠ 자산 도달 | `claude plugin details`의 Skills 개수 |
| 규칙 카드 도달 | 소비자 `.claude/rules/`를 눈으로 |
| 훅 실제 발화 | 소비자에서 `doctor --usage` |
